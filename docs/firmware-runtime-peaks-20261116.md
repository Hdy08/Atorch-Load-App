## 一次刷入的实测顺序

1. 保持独立供电，负载关闭，用官方程序刷入 RT1H。先不进关于页观察 60 秒，确认显示和按键正常；然后查看两次 `Hxx`。若再次出现刷完立即闪屏，结束本包测试并使用恢复包。
2. 使用设备面板预先选择 CC，目标设为 **0.1 A**，保持负载关闭。关闭官方程序和重构应用，使本轮记录工具独占 USB。后续启停使用设备按键，记录期间不改变目标值、保护或校准参数。
3. 开始 600 秒只读采集。在同一次采集中依次接入下表四档电源；**每次更换电源或电压前先关闭负载**。各档先观察空载约 10 秒，再按键启动 0.1 A 约 15 秒，最后关闭约 10 秒。各档回报设备显示的电压、电流、功率及是否异常；这些面板值和软件值还不构成参考仪表校准。
4. 记录完成后，保持独立供电和相同输入，拔插 USB，再运行 30 秒。计数和极值应接续，先前采到的约 20 V 最大值应保留；读取过程中不要拔线。
5. 停止负载并结束采集后，断开独立电源、USB 和被测输入，确认屏幕熄灭，再按 **5 V** 输入重新接通，保持负载关闭，运行 30 秒。计数应重新开始，电压最大值从本次约 5 V 的采样重新建立，不应保留上一次的约 20 V。

| 5 V      |    0.1 A |        0.5 W | 首次非零采样、空载 / 运行切换  |

## USB 格式

请求固定 64 字节：前 8 字节 `55 05 01 53 46 48 01 00`，其后 54 个零，末尾 `EE FF`。`FH 01 00` 为版本标记，不是认证密钥。HIDAPI 前置零 report ID 后写入 65 字节。

| 回复偏移 | 含义                                                              |
| -------- | ----------------------------------------------------------------- |
| `0..7`   | `AA 05 01 53 48 01`，状态码，保留零                               |
| `8..31`  | 32 位序列、周期循环数、采样数、tick、粘性标记、选定字段异或校验   |
| `32..55` | 六个小端 binary32：V 最小、V 最大、A 最小、A 最大、W 最小、W 最大 |
| `56..59` | READY                                                             |
| `60..63` | `01 01 EE FF`，两个状态头检查标记和帧尾                           |

状态码 `0` 为一致副本，仍需检查校验、READY、有限值和上下界；`1 / 2 / 3 / 4` 分别表示 ROM 不符、回调上下文不可用、状态头不符、三次一致读取仍忙碌。错误回复的残留数据不能作为极值，旧 G 格式也不能按此布局解释。

## 实现与核验边界

保留 RT1G 的 64 字节任务拥有状态、`0x120` 字 / 1,152 字节任务栈、64 字节长期帧和原分配 / 上下文路径，不划定新的固定 RAM，不增加 USB OS API / TCB 查询。六个 payload 字改为 V 最小 / 最大、A 最小 / 最大、W 最小 / 最大；原始瞬时温度仍由原协议提供。

首个有效采样由 READY 判定，同时初始化各通道上下界；后续仅扩展界限，32 位采样计数回绕不会清除已有极值。有限 binary32 用整数排序键比较，负数按数值顺序，正负零统一为正零，不调用浮点或 OS 比较接口。非有限源置粘性错误，错误回复不暴露为有效极值。没有新增调节环路、保护算法或持久化字段。

采样仍以至少 100 个 OS tick 为间隔，极值仅覆盖实际采到的点；短暂尖峰可以漏掉，不能称为连续硬件峰值捕获。状态重启即清空，没有运行中清零命令。只读导出不依赖主机持续连接，USB 断开期间后台仍按原任务调用采样。

新的数值正文、长分支、常量地址和执行区间在制作时待实测；现已取得本轮正常后台 / USB 路径和关于页反馈，不能外推全部指令分支或条件。离线核验比较实际生成指令的字段模型与固定 SLEIGH，保留明确的 CALL / RETS、关于页任务查询和并发出版模型；不宣称完整模拟调度、中断、MMU、物理 CSYNC 或真实栈余量。带盐异或只覆盖选定字段，等值极值对会抵消，不能当作完整内存校验或密码学 CRC。
