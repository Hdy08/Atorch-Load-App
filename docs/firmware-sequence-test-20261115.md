## 指令、地址与计算过程

关于页公共路径在 `0x01E36AC4` 已将型号文字 `BW150` 的地址 `0x01E5415F` 放入 `r10`。原指令随后把版本文字 `V1.1.0` 的地址放入 `r8`；本轮改为复制 `r10` 后加 7：

```text
原厂：
01E36AC4  CA FF 5F 41 E5 01    mov r10, #0x01E5415F  ; 保留
01E36ACA  C8 FF 65 41 E5 01    mov r8,  #0x01E54165  ; 被替换的 6 字节

本轮：
01E36AC4  CA FF 5F 41 E5 01    mov r10, #0x01E5415F  ; 原样
01E36ACA  A8 08                mov r8, r10           ; 2 字节
01E36ACC  88 FC 07 00          add r8, r8, #7        ; 4 字节
01E36AD0  00 E0 2D 03          jeq r0, #0, 0x01E3712E ; 原样继续
```

计算结果为 `0x01E5415F + 7 = 0x01E54166`。这正是原有 `V1.1.0` 中首个 `1` 的地址，后面的零终止字符串为 `1.1.0`。原始型号、版本及 USB 字符串的字节都保持原样，显示变化依赖本轮指令组合算出的地址。

| 项目               | 值                     |
| ------------------ | ---------------------- |
| 替换起始映射地址   | `0x01E36ACA`           |
| APP 内偏移         | `0x369AA`              |
| 升级包内偏移       | `0x3AACA`              |
| 替换前 / 后长度    | 6 / 6 字节             |
| 续行地址           | `0x01E36AD0`，前后相同 |
| 源通用寄存器       | `r10`                  |
| 被改变的通用寄存器 | `r8`                   |
| 算出的文字地址     | `0x01E54166`           |

本轮不增加文件、额外代码区、跳转或函数调用，也不改变后续指令的位置。它是原位置的指令序列实验，不代表独立新增函数或完整自研固件已经验证。

## 指令与寄存器检查

新增字节按本机已有 q32s 指令定义编码，再由固定摘要的 SLEIGH 模块反汇编及转换为 P-code；另以独立的位域解码函数解释所选 MOV / ADD，比较通用寄存器结果。该位域函数单独识别原 6 字节立即数 MOV、2 字节寄存器 MOV 和本轮 4 字节带符号立即数 ADD。

- 原厂 / 本轮两种输入、文字标签 / 位图标签两条分支、8 种初始寄存器模式，共 **32 组、144 条选定的通用寄存器更新**，两种模型的结果一致。
- 原厂各组的绘制参数为 `BW150` / `V1.1.0`；本轮为 `BW150` / `1.1.0`。
- 对本轮两条指令另外检查 **267 组源值、534 条更新**，包含零值、符号边界、32 位无符号回绕及固定随机种子的输入；结果均为 `r8 = (r10 + 7) mod 2^32`，其他通用寄存器在所选两条指令中保持原值。
- 三项消融检查只在内存中执行：将加数改为 0 得到 `BW150`，改为 6 得到 `V1.1.0`；去掉源地址复制后得到错误指针 `0x7`。这些检查区分了加法和源地址复制各自的作用，没有输出相应刷写包。

这里没有执行中间的原厂函数调用，也没有模拟完整 UI、启动流程或外设。绘制参数处是观察边界；原绘制函数的完整运行及通用寄存器跨调用行为仍依赖后续实机观察。

## 状态标志与控制流检查边界

所用 q32s 模块的 README 明确将 flags、stacks 等列为未完成内容；本机 ADD 的 P-code 只表达通用寄存器加法。因此，**本轮没有证明硬件 PSR 状态标志保持不变，也没有把缺失的标志更新当成“硬件不更新标志”的证据。**

本轮额外核对了三段原样保留的直接上下文：

| 范围                         | 指令数 | 所核对的结果                                 |
| ---------------------------- | -----: | -------------------------------------------- |
| `0x01E36AD0` 至 `0x01E36AD4` |      1 | 下一分支直接比较 `r0` 与 0                   |
| 非零分支首个原调用之前       |      7 | 只有原有 MOV / SW，所用 P-code 未见 PSR 输入 |
| 零分支首个原调用之前         |      8 | 只有原有 MOV / SW，所用 P-code 未见 PSR 输入 |

这将局部检查明确限定到两个分支的首个原调用之前；不据此保证被调用函数、中断、全部 PSR 位或整个程序的行为。该限制保留在机器可读摘要和完整证据中。

另外，针对每个对齐半字中的已知控制指令前缀，共尝试 77,988 处：73,002 处可由模块解码，4,986 处返回 `BadDataError`。可解码结果中没有发现直接跳入原 6 字节替换区的控制转移；对替换区三个对齐地址的 32 位字面值搜索也未发现引用。扫描包括可能的数据，且无法解析不支持的指令及计算出的间接目标，因此不等同于完整控制流证明。

参考的本机定义包括 `.local/ghidra-jieli/data/languages/q32s.slaspec`、`q32s_ins_arithops.sinc`、`q32s_ins_move.sinc`、`q32s_ins_progflow.sinc` 与 `.local/jielie/cpu/q32s.md`；各自 SHA-256 已固定在制作工具及摘要内。
