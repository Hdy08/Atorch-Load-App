## 同一次刷入的测试顺序

1. 保持设备稳定供电，不接被测电源，用官方程序刷入 **RT1G**。完成后先不进入关于页，观察 **60 秒**：显示、按键及原有界面正常，无闪屏或反复重启。
2. 进入关于页，仍应显示 **`F00…FFF`**，例如 `F01`。这是刻意保留的 RT1F 后台计数文本，并非误刷旧包；RT1G 由 USB 回复中的 `G` 标识区分。退出等待 **10–20 秒**后重进，计数应有变化。
3. USB 连电脑，关闭官方程序和重构应用，运行下面的只读记录工具 **300 秒**。它交替读取新诊断和原厂监测，记录六项数值、完整 32 位计数、tick、序列、粘性标记及选定字段校验；还读取前后原厂设置。它不刷写、不改设置、不启停负载。运行时观察设备界面和按键是否仍正常。
4. 工具结束后，**保留独立供电**，断开再接 USB 数据线，重新运行 **30 秒**。原厂重新注册若清空回调上下文，后台应重新发布有效指针，诊断恢复；计数应接续增长。若拔线会使设备断电，则改记为冷启动，不把它写成保持计数的重连。
5. 完全断电后重启，再运行 **30 秒**，确认本次启动的计数从新一轮开始增长、无诊断错误；具备条件时再用原监测应用确认 USB / BLE 仍可连接。所有实验结束后统一刷回原厂恢复包并确认正常，无需每个子项都重复刷写。

## 接入方式与边界

RT1F 的 326 条后台 / 关于页核心指令保持原地址和操作；仅 12 处常量指针重定位，计数文本及 ROM 字节对照表内容保持。栈仍为 **`0x120` 字 / 1,152 字节**，长期状态仍占 64 字节。入口、原厂分配 / 初始上下文、物理堆结束参数及任务正文保持 RT1F 方案。

本轮增加一个周期入口包装：临时保存 16 字节，确认原应用 HID 接收回调仍注册后，将任务自身 SP 推导的状态指针写入原回调的 `priv` 上下文字段，释放临时帧，再尾跳原 RT1F 周期核心。该字段是原回调结构已有的应用指针，**不是额外划定的空闲 RAM**；原接收函数没有使用传入的上下文参数。若回调尚未注册或属于别的回调，包装不写这个字段；原厂重置后可由后续周期重新发布。

之所以这样接入，是因为匹配版本的官方 SDK 把 HID 接收处理注册为端点中断处理函数，并直接调用应用回调。USB 路径不新增 `xTaskGetHandle` 或其他 OS API，也不读取 TCB；已验收的关于页查询仍保留。官方源码、固定提交号和摘要保存在 `artifacts/firmware-runtime-usb-primary-20261116/`，原固件的对应指令块及地址另存于本轮 `analysis.json`。SDK 相符和静态定位不等于完整中断系统的实机证明。

新 USB 处理先核对 8 段共 268 字节 ROM 合约，再核对回调归属、上下文指针对齐及状态头。它只读后台状态，使用原接收函数已有的 `[SP+48, SP+112)` 64 字节回包缓冲区和原有复制 / 发送路径。`SP+[0,8)` 保存本次请求指针和重试序列，局部 ROM 比较调用另用 4 字节；其内部没有新 OS API 栈开销。真实中断栈余量仍需实机观察。

奇 / 偶序列读最多重试三次，成功才将有效状态返回主机；忙碌或错误回包的残留负载不作为采样数据。原 USB 接收函数除分发处 4 字节外保持原字节，原有命令在分发边界的 GPR / SR、内存访问行为对照一致；未把完整原 USB 驱动、控制器和中断行为模拟出来。

新增包装及 USB 代码共 **302 字节 / 110 条**，含保留核心共 1,152 字节 / 436 条，结束于 `0x01E974B8`。PC 上限改为 **`0x01E974C0`**，本台设备已实际执行新增后台 / USB 正常路径，并完成一次保持供电重连和一次冷启动；这不覆盖所有新增地址、故障分支或中断栈余量。没有把此前 BATCH8 的较低边界验收套用到此处。包含常量使用 2,624 / 3,200 字节 APP 扩展，整包长度不变，非 APP 内容保持，原厂逆向恢复逐字节一致。

## USB 诊断格式

请求固定 64 字节，前 8 字节 `55 05 01 52 46 47 01 00`，末 2 字节 `EE FF`；`FG 01 00` 是版本 / 格式标记，不是安全认证口令。其余字节零填充。只读工具仅构造原厂 `03 / 05` 和这一 `52` 查询；原厂查询仍用原格式。旧 RT1 / RT2 / RT3 的 `RT` 回复格式不兼容，本工具明确拒绝。

| 回复位置 | 含义                                                                   |
| -------- | ---------------------------------------------------------------------- |
| `0..3`   | `AA 05 01 52`                                                          |
| `4..7`   | `47`（G）、格式版本 `01`、状态码、保留 `00`                            |
| `8..11`  | 32 位奇 / 偶发布序列                                                   |
| `12..15` | 32 位周期循环数                                                        |
| `16..19` | 32 位快照数                                                            |
| `20..23` | 快照 OS tick                                                           |
| `24..27` | 粘性标志：`02` 非有限源、`04` 选定字段完整性错误                       |
| `28..31` | RT1F 带盐异或校验                                                      |
| `32..55` | 电压、电流、功率、MOS / 探头 / CPU 温度，6 个原始 IEEE binary32 小端字 |
| `56..59` | 独立 READY 标记                                                        |
| `60..63` | 两个状态头检查标记 `01 01`，帧尾 `EE FF`                               |

状态码 `0` 表示已取得一致副本，主机仍需检查序列、READY、粘性标志、有限值和校验；`1` 为 ROM 不匹配，`2` 为回调 / 指针尚不可用或不符，`3` 为状态头不符，`4` 为三次重试后仍忙碌。主机对 `2 / 4` 及尚无首份发布有有限次数等待，持续异常会结束并保留日志。

异或校验覆盖 RT1F 的十个选定字段，不覆盖所有字段，存在抵消碰撞，不能替代完整内存保护或密码学 CRC。`CSYNC` 的物理排序、完整调度 / 中断、页增长和栈余量未在主机中模拟。计数 / tick 保持 32 位回绕处理，不假定 OS tick 频率；工具记录观测频率，不预设 1 kHz。

原协议对照的单位分别为 V、A、W、°C。诊断和原厂回复是相邻查询，不是同步采样；设置的数值差阈值只是静稳读数对照工具，**不构成校准、量程、带载、保护或测量精度验收**。温度符号、电流符号与小数缩放按 `crates/protocol/src/lib.rs` 的现有线协议处理。
