# 固件刷写规则与官方程序对齐

2026-11-16，用户明确要求“去除应用中固件刷写限制，和官方程序保持一致即可”。本次修改仅涉及固件检查、USB 升级入口、平台接口识别及其测试，没有刷写或读取实机设备。

## 文件检查

官方 BW600 PC V1.0.8 文件入口使用 `.bin` 筛选、拒绝空文件，并以 `0xFA000`（1,024,000）字节为上限；已追踪路径没有检查型号、AC632N 封装或整文件 SHA-256。此处沿用已有官方程序静态核查结果，本次不修改主聊天的认证分析及实机实验文档。

应用现在对所有非空且不超过 1,024,000 字节的 `.bin` 文件开放 Windows / Android USB 刷写：

- 删除固定 BW150 V1.1.0 SHA-256 白名单，不再只允许原厂参照包。
- 删除文件头必须匹配 AC632N、至少 64 字节的条件。AC632N 仍可识别显示；其他内容显示“二进制固件”。
- 删除文件名型号不匹配提示及对应的限制，不使用文件名推断硬件兼容。
- SHA-256、CRC16、块数和首尾包继续显示，但摘要不决定是否允许刷写。
- 所有文件的离线预演统一走实机使用的 USB 外层，不再因文件摘要不同切换预演路径。

非 `.bin`、空文件、超过 1,024,000 字节、无效编码和路径型文件名仍拒绝。文件大小上限是与官方文件入口对齐，不是移除 USB 分块协议的容量边界。

## Windows / Android USB 与完成状态

Windows 根据 `APP / IAP` 制造商及对应 HID Usage 判断工作模式，不再要求产品名等于 `ATORCH BW150 V1.1.0 / V1.0.2`。Android 保留 HID class 及双向 64 字节 interrupt endpoint 检查，只以 `APP / IAP` 制造商识别模式，不限制产品型号和版本。两平台继续使用原有 VID / PID 设备枚举。

精确 IAP report descriptor 的捕获字节不再作为准入白名单；可读取的描述符写入诊断日志，无法读取时不阻止握手。实际报文长度、分块回显、CRC、序号、错误应答和超时仍由传输引擎核对。这些检查保障协议状态，不代表固件适配、物理显示或真实 Flash 回读已验收。

确认刷写后，服务自动保存并关闭当前记录，结束监测线程，独占 USB；不再因记录仍在进行、未回读停止状态或输入非零而拒绝开始。APP 设备发送官方进入 IAP 命令，已处于 IAP 的设备直接从第 0 块传输。仍需用户点击既有确认按钮，升级期间其他设备操作继续互斥。

完成规则改为与官方程序一致：收到传输引擎认可的零状态 FF，标记设备已确认刷写完成。随后尝试重新枚举 APP 并读取参数 / 遥测：

- 新 APP 的产品名、版本和序列号可与刷写前不同。
- 正常回读不再要求输入为零或负载停止。
- 回读通过并重新打开监测连接后，显示正常应用回读已通过。
- 已有 FF、但应用未出现或无法恢复监测时，仍显示设备已确认刷写完成，并保留具体重连错误；不会声称正常应用已验证。
- 没有 FF、CRC / 序号错误、设备拒绝、超时或取消仍不显示刷写完成。

如果同时有多个重新枚举候选，服务不猜选目标；如 FF 已确认，该问题仅影响后续监测恢复状态。固件数据包仍仅传输一次，无隐式重试，烧写阶段不能取消。

## 实现及验证

修改涉及 `crates/protocol/src/firmware.rs`、`crates/device/src/firmware.rs`、Tauri 固件检查命令、`FirmwarePanel.tsx` 和 Android `UsbPlugin.kt`。协议中保留的原始 IAP 描述符仅为捕获格式参照，不参与本次准入判断。

后端回归覆盖任意文件头、1 字节文件、58 字节整块与跨块边界、最大文件上限、修改版包 USB 预演，以及模拟 APP → IAP → 不同型号 / 版本 / 序列号 APP 的完整升级。另验证新应用未重连时 FF 仍单独表示完成，错误回显 / 序号 / FF、缺失 FF、取消和超时不会误判。界面回归覆盖自定义文件名、其他产品版本、记录进行时确认刷写及完成状态的准确呈现。

本轮为离线测试及编译验证；没有执行真实固件传输，没有将新增文件选择范围表述成这些固件已获硬件兼容验收。历史冻结固件、捕获及其 manifest 不改动。

本阶段验证结果：`atorch-protocol` 26 项和 `atorch-device` 42 项测试全部通过；固件页面 Playwright 8 项全部通过；TypeScript 检查、前端生产构建、Windows `cargo check -p atorch-app`、协议 / 设备 Clippy 以及 Android USB 插件 `compileDebugKotlin` 通过。界面测试产物位于 `artifacts/firmware-open-policy/`。此后用户要求将本侧边聊天改动与暂时关闭 10 Hz 一并提交并生成 Windows 安装包，交付产物位于 `artifacts/side-chat-release-20261116/`；未部署到已连接设备。
