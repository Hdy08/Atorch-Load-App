## 首读超时与原厂恢复

最初 `usb300-01` 在第一个 `03` 请求后超时，未发送 `52`，保存零组采样。随后有限原协议探测先出现 `05` 超时，再取得 `03`；下一次六个 `03 / 05 / 52` 请求均回复。之后五个完整窗口完成。

用户回刷原厂后，`original-restored-01 / 02 / 03` 的首次 `03` 均超时；`original-sequence-01` 中前两个 `05 / 03` 超时，后两个 `05 / 03` 回复。最终 `original-restored-04` 在同一打开的句柄内允许首次设置查询最多三次：第一遍超时，第二遍成功；之后五次 `05` 和最终一次 `03` 均成功，序列号及设置与实验前一致，句柄已关闭。

因此恢复状态由用户正常反馈及实际原协议回读共同记录，**首读超时的根因仍未确认**。不能仅依据这类超时推断实验固件复位，也不能因为后来回复正常而删除先前失败。恢复后未发送实验 `52`，未独立回读整个 Flash，不能将 USB 产品版本文字或用户恢复操作当作逐字节 Flash 摘要核验。

本次所有原始记录合计发出 824 个只读查询，记录 816 个回复；8 个未获回复请求均保留在相应失败 / 探测记录。完整采集窗口本身共 800 个查询，均取得回复。新增证据复核所有已记录出站字节均等于允许的 `03 / 05 / 52` 读取格式；原厂恢复后的检查仅允许 `03 / 05`。没有发出设置、启停或刷写指令。
