## 相对 RT1B 的新增内容

### 状态由原厂任务分配器拥有

原数据任务注册处的栈深度从 `0x100` 字增加至 `0x130` 字，即 **1,024 → 1,216 字节，增加 192 字节**。同一任务的函数指针改到短包装入口，包装入口为任务生命周期长期保留 144 字节，再转入原数据任务。原厂分配器、物理堆结束参数和早期初始化保持原字节，没有使用旧 RT1 的 `0xFA80` 固定私有地址。

参考 ROM 的任务创建路径显示，TCB `+4` 保存栈字数，`+0x40` 保存栈基址。新状态使用本任务分配区最后 128 字节：`pxStack + 0x440`。包装入口先匹配任务布局相关的参考 ROM 字节，再读取当前任务，核对深度、对齐和状态与实际 SP 的相对位置，才初始化该区。

不假定任务入口 SP 恰好是分配末端：接纳末端以下 `0..80` 字节的对齐位置，实际状态相对长期帧基址的偏移必须在 `16..96` 内。长期帧记录有界相对偏移、标记和反码；周期调用在使用它前复核。新增代码只写本任务拥有的状态 / 帧及当前调用的暂存栈，不改 TCB 字段，尤其不占用原系统已使用的 `+0x54` 应用任务标签。

192 字节分配增量扣除 144 字节长期帧，留下 48 字节工作空间增量；周期包装再临时使用 36 字节。按照所选原调用点的帧关系，局部工作空间仍比原厂多 12 字节。这是布局推导和局部模型结果，**没有测量物理栈高水位，也没有证明全部调用的栈峰值**。分配成功仍取决于设备实际剩余内存。

### 后台真正发布快照

原数据任务在已通过 RT1B 最小接入的位置执行新增周期逻辑，返回前恢复原寄存器、SP、RETS，并以原参数进入原 OS 延时。周期路径内部没有新增 CALL。

首次调用发布第一份快照，以后距离上次达到 100 个 OS tick 才更新；不假定 OS 的 tick 频率，不把“100 tick”写成“1 秒”。保存内容包括全 32 位循环次数、快照次数、tick、电压 / 电流 / 功率、MOS / 探头 / CPU 温度六个 IEEE binary32 原始字，以及序列号、有限值标志、选定字段 XOR 校验和、独立 READY 标记、布局及边界标记。

写入由原数据任务单独负责。先发布奇数序列、更新内容，最后发布偶数序列；生成代码包含 `CSYNC`。每次周期调用先检查旧选定字段校验，发现损坏会保留错误标志，即使随后产生新快照也不会抹掉历史错误。计数或 READY 变为零仍要验证校验和，不通过“零”跳过完整性检查。标志、计数和快照均为易失状态，完全断电启动后重新初始化。

XOR 是诊断一致性检查，不能提供密码学完整性，也不覆盖全部 RAM。六项异步源按顺序读取、作为一条软件记录发布；这不代表六项由 ADC 同时转换，也未确认单位、映射或电气精度。

### 关于页读取后台结果

关于页先核对全部 **304 个参考 ROM 字节**，再调用原厂已使用过的 `xTaskGetHandle`，查找原任务在 ROM 中截短后的名字 `cl24_data_t`。返回的活动 TCB 用于读取栈基址和大小，核对布局后，以最多三次序列检查取得一致快照；关于页不增加后台计数、不写后台状态。

正常版本位置显示 **`C00`～`CFF`**：字母 C 后两位是十六进制后台快照计数的低 8 位，例如 `C09 → C0A`，`CFF → C00` 为正常回绕，后台完整计数仍是 32 位。每一个正常码和错误码都是 Flash 中的固定文本，原厂绘制流程不接收临时 RAM 文本指针。重新进入关于页能读取当时的计数；不要求原页面原地自动刷新。

| 结果         | 含义与处理                                                                              |
| ------------ | --------------------------------------------------------------------------------------- |
| `C00`～`CFF` | 一致快照的计数低 8 位。离开页面等待后再进入，应继续变化；单个码本身不代表整包全部通过。 |
| `C:ROM`      | 所选 ROM 字节不匹配；跳过新增任务查询和 TCB / 状态读取。记录准确码，本轮不按通过。      |
| `C:MEM`      | 任务栈布局、大小、对齐或状态标记不匹配。本轮不按通过。                                  |
| `C:NONE`     | 原厂任务查询返回空。本轮不按通过。                                                      |
| `C:WAIT`     | 尚无第一份完整快照。启动后短暂出现可以再次进入检查；持续出现不按通过。                  |
| `C:CRC`      | 选定字段 / READY 校验异常，或此前发生过后台校验异常。本轮不按通过。                     |
| `C:NUM`      | 后台曾读取到 NaN / Infinity；记录后即使后续正常仍保留至重启。本轮不按通过。             |
| `C:BUS`      | 三次读取都遇到写入或序列异常。短暂出现可退出再进入；反复或持续出现不按通过。            |

本轮没有新增私有 USB 命令，原厂 USB 接收函数逐字节一致，原有 BLE 代码也未修改。**关于页只导出计数与诊断状态，尚不能从它逐项核对六个快照数值、符号、单位或测量精度。** 完整数值导出、易失极值和带载整包验收仍需后续候选；不能直接恢复旧 RT2 / RT3 测试。

## 历史验收计划（RT1C 已失败，停止执行）

1. 从已恢复正常的原厂状态开始，先断开负载输入并保持稳定控制供电。使用此前成功的官方流程，选择本目录的 **RT1C** 刷入。
2. **先不要进入关于页**，观察主界面约 60 秒，检查启动、原厂监测和按键没有立即闪屏、非预期重启或负载启停。发生异常则记录阶段，沿已成功的恢复流程回原厂，不重复刷同一失败包。
3. 进入关于页记下 `Cxx`，退出至正常页面；约 15 秒后再进入记第二个码，再离开一段时间后记第三个码。应有计数推进；`FF → 00` 是正常回绕。若码相同，可再用较短间隔复核，避免恰逢整圈回绕。不要求固定每秒变化多少次。
4. 若设备具有独立稳定供电，可只断开电脑通信、保持设备通电，在普通页面等待约 30 秒后重进关于页，检查计数继续推进。若 USB 同时承担唯一供电，则不要把断电当作“断通信”，本项标记条件不具备即可。
5. 同一次刷入检查已有页面、按键、原有 USB 监测及具备条件的 BLE 功能，操作期间和之后再进入关于页检查计数和错误码。**先做无负载输入的本轮回归，不把本包当作旧 RT3 带载包。** 对没有测试条件的具体接口注明未测。
6. 完全断电后冷启动，先观察主界面，再按步骤 3 取得至少两个间隔读数。新启动的计数重新产生，不要求恰好看到 `C00`；进入页面前已发布快照是正常的。
7. 最后回刷本目录的原厂一致恢复包，确认原厂版本、正常显示及原有功能恢复。

顺利时是 **1 次 RT1C + 1 次原厂恢复，共 2 次完整传输**，上述项目集中完成，不为每项重新刷入。建议反馈：未进关于页的启动情况、三次 `Cxx` 读数、独立供电断通信项是否具备条件、原有功能、冷启动后的两个码、原厂恢复结果。未单独报告的时长、数值、接口或带载项目不由整体反馈补写。
