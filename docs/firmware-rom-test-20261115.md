## 八组测试与通过位

`R` 标识 ROM8，后两位是八组通过位图。普通结果检查失败时清除所属位，恢复包装代码状态并继续其他组。若 CPU 异常导致重启，可能无法显示最终位图，不从复位本身推定具体哪组失败。

| 通过位 | 接口      | 向量数 | 内容                                                                   | 仅该组失败 |
| ------ | --------- | -----: | ---------------------------------------------------------------------- | ---------- |
| `01`   | `strlen`  |      6 | 空串、单字节、型号与普通字符串、16 字节串、高位字节，以及不同对齐      | `RFE`      |
| `02`   | `memset`  |      6 | 长度 0 / 1 / 7 / 16 / 17 / 32、对齐与不对齐、填充值低字节转换          | `RFD`      |
| `04`   | `memcpy`  |      6 | 长度 0 / 1 / 7 / 16 / 17 / 28、不同源与目标对齐                        | `RFB`      |
| `08`   | `memmove` |      8 | 零长度、单字节、前后方向重叠、非重叠、原地移动、31 字节紧邻重叠        | `RF7`      |
| `10`   | `memcmp`  |      6 | 零长度、相等、不同对齐、首 / 中 / 末字节差异、高位字节、返回符号与差值 | `REF`      |
| `20`   | `strcmp`  |      6 | 空串、相等、前缀长短、后部字符差异、高位字节                           | `RDF`      |
| `40`   | `strcpy`  |      6 | 空串与不同长度、不同源 / 目标对齐、零终止、高位字节、原目标地址返回值  | `RBF`      |
| `80`   | `strncmp` |      6 | 长度 0、截断到差异之前、包含差异、遇零终止、不同长度和高位字节         | `R7F`      |

每个向量包含八项运行时检查：`r6`、`r4`、`r5`、`r7` 保持，返回值，缓冲区前保护字，后保护字，以及完整 32 字节缓冲区。因此共有 **50 × 8 = 400 项**。完整缓冲区检查逐字节执行，在统计中算一项；只读接口同样核对私有缓冲区与保护字不变，Flash 源输入受模型的只读约束。

所有内存操作限定在本次调用私有栈帧中的缓冲区。源字符串位于本包新增的 Flash 常量区，并为参考实现的字读取路径保留终止后的可读填充。测试没有分配长期全局 RAM，没有初始化新的系统任务或注册回调，也没有调用参数存储、负载、Flash 写入或其他外设控制入口。

## 接口来源与调用方式

继续复用 B5 清单固定摘要的官方 BD19 参考 `rom.lst` 和 CPU 寄存器定义。在该参考 ROM 中，`0x00106EE4…0x00106F00` 每四字节一个导出入口，分别为 `memcpy`、`memmove`、`memcmp`、`memset`、`strcmp`、`strcpy`、`strlen`、`strncmp`。`memcpy` 和 `memmove` 两个导出入口都跳到参考实现 `0x00100040`。

本轮另外固定核对原厂 APP 的七处调用机器码，与上述对应导出地址的低 25 位关系一致；没有把线性扫描候选数当作真实运行调用次数，也没有据此证明整个设备的 PC 位宽或地址回绕规则。现有 SLEIGH 在这些相对调用点给出的未归一化地址为 `0x02106Exx`。**新代码通过寄存器持有官方导出表中的绝对地址，再使用已验收形式的间接 CALL，避免把这些未归一化地址写进新函数表。**

这仍是参考 ROM 和原厂 APP 调用字节之间的静态关联。当前没有物理 ROM 回读，不把参考 SDK 与实物 ROM 的版本一致性记为已确认；本轮实机反馈将验证这八个接口在当前设备上的互操作结果。

离线执行分为两条路径：新增包装代码按已有独立位域解释和 SLEIGH P-code 对照；ROM 内部按官方反汇编表达式解释，与相同原始字节生成的 P-code 逐步对照。没有用简单的主机 `memcpy` 替代整段 ROM 执行，也没有跳过对齐、重叠、零终止和返回路径。

## 沿用 BATCH8 的布局和栈上限

| 项目                         | ROM8                           |
| ---------------------------- | ------------------------------ |
| 升级包总长                   | 643,072 字节                   |
| APP 扩展                     | 3,200 字节，与 BATCH8 相同     |
| APP 长度                     | 621,464 字节                   |
| 新增指令代码                 | 462 字节                       |
| 扩展区使用 / 剩余            | 3,124 / 76 字节                |
| 最大额外栈                   | 132 字节，与 BATCH8 相同       |
| 包装代码局部帧               | 104 字节                       |
| 可变数据缓冲区               | 32 字节，前后各有 4 字节保护字 |
| 配置资源 / P11 后移          | 3,200 字节，文件内容不变       |
| 有效载荷结束 / 整包 FF 尾部  | `0x9CFA6` / 90 字节            |
| 新增指令结束 / Flash PC 上限 | `0x01E97206` / `0x01E97220`    |
| 指令后零 / NOP 填充          | 26 字节                        |

最大栈由外层 RETS、104 字节局部帧、测试循环 RETS、参考 ROM 最深 20 字节保存帧组成，总计 132 字节。Flash PC 上限覆盖新代码及末尾填充，参考 ROM 的所有选定指令也位于原配置的 `0x00100000…0x00110000` ROM PC 范围内。其他 PC 范围和 `EMU_CON` 保持原厂配置。

原 APP 仅改变原关于页 6 字节钩子和 PC 上限立即数中的两个字节，测试从原位置进入并回到 `0x01E36AD0`。结果文字存放于 Flash；返回时只让 `r8` 携带所选文字指针，其余选定寄存器、SP 和 RETS 在模型中恢复。

为了在已验收的扩展长度内保留所有向量，期望缓冲区采用“32 位差异位图 + 改变的字节”存储。未改变的第 `i` 字节期望值为原始种子 `i`，改变的位置从紧随位图的字节表读取；实际运行仍检查全部 32 个位置和两侧保护字。

## 离线检查及边界

本轮检查覆盖：

- 64 组初始寄存器 / 栈位置组合，每组完整执行所有 50 组向量、36,005 步，共 2,304,320 步，均返回 `RFF`。新增 177 条指令和选定参考 ROM 的 256 条指令分别核对边界及语义。
- 全部 255 种非空组失败组合：在电脑内存中改变对应组第一条向量的返回值期望，验证位图、失败清理和后续组继续执行。
- 100 个逐向量表字节故障：每条向量分别破坏返回值期望、替换完整缓冲区期望指针，要求在指定组、向量和检查项失败。
- 300 个运行模型扰动：在指定 ROM 调用返回后分别改变四个被检查寄存器或两个保护字，验证相应检查和失败状态恢复。这些是模型状态注入，与前述实际改变电脑内存中 APP 字节的测试分别记录。
- 两条原绘制分支、八种初始模式，共 16 组参数检查应得到 `BW150` / `RFF`。
- 原厂一致重建、确定性重建、撤销扩展恢复原厂逐字节一致；第三方完整解包、7 项结构 / CRC 负例，以及之前七轮 7 份冻结清单和其覆盖的 43 个文件复核。
- 实验包及原厂一致恢复包分别经生产协议层进行无设备预演，均为 `offline=true; Complete; 11088/11088`、末块 26 字节。日志位于 `artifacts/firmware-rom8-protocol-20261115.txt`；模拟应答不作为设备真实 EE / FF 或新抓包记录。

现有 SLEIGH 省略 CALL 的 RETS 自动更新，多寄存器 PUSH / POP 也只有 RETS / PC 的部分语义。本轮显式补入这些缺失部分：按约定的匹配保存帧补足通用寄存器，再执行原有 RETS / PC 语义。**模型在同一约定下的一致性，不是独立证明硬件栈字节顺序或完整 C ABI。** 选定原厂库代码已有这些保存指令，新固件的包装代码仍使用之前验证过的单独 RETS 保存和显式局部栈形式。

运行时逐向量检查四个寄存器和内存效果，但未仿真硬件 PSR、中断、缓存、完整 UI 或所有任务负载。132 字节上限与 BATCH8 相同，不据此保证任意运行场景的任务栈余量。硬件异常可能先复位而没有结果码；本包没有新增异常恢复器或独立自研启动流程。
