## 修改内容

关于页公共代码在 `0x01E36ACA` 将版本文字的地址放入 `r8`。原指令指向 `V1.1.0`，新指令改为指向已经存在的 `BW150` 型号文字：

```text
原指令：C8 FF 65 41 E5 01    mov r8, #0x01E54165  ; V1.1.0
新指令：C8 FF 5F 41 E5 01    mov r8, #0x01E5415F  ; BW150
```

| 属性                    | 值                            |
| ----------------------- | ----------------------------- |
| 指令映射地址            | `0x01E36ACA`                  |
| 指令在 APP 文件中的偏移 | `0x369AA`                     |
| 指令在整包中的偏移      | `0x3AACA`                     |
| 实际改变的 APP 字节偏移 | `0x369AC`，`65` → `5F`        |
| 实际改变的整包字节偏移  | `0x3AACC`，编码后 `6C` → `56` |
| 指令长度                | 前后均为 6 字节               |
| 目的寄存器              | 前后均为 `r8`                 |

这是**已有 MOV 指令的立即数操作数修改**，不是修改字符串，也没有插入代码、增加跳转、改变指令长度或移动任何文件。除这一操作数字节外，APP 全部字节保持原样；入口、调用位置、硬件控制和参数逻辑的原始代码字节均未修改。不据此宣称任意外设行为已得到实机验证。

版本字符串、型号字符串、USB 字符串和第一轮研究中发现的信息构造后缀均保留。选用的两个地址都指向原有零终止 ASCII 字符串，仍通过原来的文字绘制函数显示。

## 指令语义和寄存器传递验证

本轮使用既有 q32s 指令定义重新反汇编并转换为 P-code。原指令转换为 `r8 = 0x01E54165`，新指令转换为 `r8 = 0x01E5415F`；两者均只有一项通用寄存器 COPY，另有标记指令位置的 IMARK。

另外实现了受限的独立位域解码：检查 16 位首字中的组号、操作码和目的寄存器，再从后两个小端半字取得立即数；对短寄存器 MOV 则检查其组号和源 / 目的寄存器。该方法与 P-code 的寄存器更新逐步比较。

已检查的显示数据流是：

```text
0x01E36AC4  r10 ← BW150 字符串地址
0x01E36ACA  r8  ← 原版本地址 / 本轮改为 BW150 地址

文字标签分支：
0x01E36B38  r2 ← r10    → 0x01E36B3A 调用原文字绘制函数
0x01E36B4A  r2 ← r8     → 0x01E36B4C 调用原文字绘制函数

位图标签分支：
0x01E3719E  r2 ← r10    → 0x01E371A0 调用原文字绘制函数
0x01E371B0  r2 ← r8     → 0x01E371B2 调用原文字绘制函数
```

共检查原厂 / 修改后两种输入、两条显示分支、四种初始寄存器模式，合计 **16 组、64 条 MOV 寄存器更新**；位域解码与 P-code 结果全部一致。原厂各组取得 `BW150` / `V1.1.0` 两个绘制参数，修改后各组取得 `BW150` / `BW150`。

这里的模拟只执行选定 MOV 的寄存器传递，并在文字绘制参数处观察结果；没有执行中间的完整函数调用，也没有模拟整个 UI、启动流程、Flash、USB 或硬件。它验证选定指令的预期参数变化，不替代实机观察。
