## 本轮测试及结果码

结果码首字符 `8` 标识本轮八组测试，后两位为十六进制通过位图。`8FF` 表示八组全部通过；普通断言失败时清除相应组的通过位，继续执行其余组。以下“断言”是分组结果检查次数，内存组还逐字节比较整个 32 字节缓冲区。

| 通过位 | 测试组           | 一次执行的内容                                                                                            | 结果断言数 | 仅该组失败 |
| ------ | ---------------- | --------------------------------------------------------------------------------------------------------- | ---------: | ---------- |
| `01`   | 调用与嵌套栈回归 | 短 CALL、长 CALL、寄存器间接 CALL、嵌套调用、两组 32 位加法回绕                                           |          6 | `8FE`      |
| `02`   | 32 位算术边界    | 8 组输入分别检查加、减、乘；含零、全一、符号边界、低 32 位截断和普通大整数                                |         24 | `8FD`      |
| `04`   | 位运算与移位     | 6 组输入分别检查 XOR、AND、左右移位组合的循环左移 5 位、算术右移 4 位                                     |         24 | `8FB`      |
| `08`   | 符号与零扩展     | 8 组输入分别检查字节 / 半字的有符号、无符号扩展，含 `7F/80/FF/7FFF/8000/FFFF`                             |         32 | `8F7`      |
| `10`   | 私有内存处理     | 零长度、单字节、不对齐、非重叠复制、前后方向重叠移动、原地移动、17 字节填充；每项核对完整缓冲区和两侧数据 |          9 | `8EF`      |
| `20`   | CRC16/Modbus     | 空输入、二进制不同长度和偏移、32 字节输入、ASCII `123456789 → 4B37`                                       |          8 | `8DF`      |
| `40`   | 有界数据帧解析   | 3 个正常载荷；错误头且 CRC 正确、错误 CRC、长度 7 / 0 / 9；核对小端载荷或拒绝值                           |          8 | `8BF`      |
| `80`   | Flash 函数表分派 | 通过新增函数指针表交替调用加、乘、异或、减，连续 32 次，每个中间结果都核对                                |         32 | `87F`      |

多组失败可以按位合并定位。例如 `8FC` 表示 `01`、`02` 两组未通过；`800` 表示没有通过位。若出现重启或异常，可能来不及显示结果，不能从复位本身推断某个测试位。

这些测试使用新写入的局部代码。数据帧是本轮独立设计的固定 8 字节内存测试帧，不是 ATORCH 的 USB / BLE 控制命令，也没有把它发送给设备外设。函数表只包含本包新增函数，没有调用未经核准的 ROM、原厂系统 API 或硬件控制函数。

## 布局和状态恢复

从原厂完整 BW150 V1.1.0 独立构建，保留原启动前缀、原版本字符串、USB 产品名，以及配置资源和 P11 的文件内容。原 APP 仅改关于页 6 字节钩子与 Flash PC 上限立即数中的 2 字节；新增自检从原关于页进入，返回原 `0x01E36AD0`，继续原绘制流程。

外层保存 RETS 和 `r0…r7`，使用 112 字节局部帧；深层嵌套 / 解析路径再使用各自局部栈。两套模型逐步核对全部通用寄存器、RETS、SP 和私有内存；返回时只让 `r8` 携带 Flash 中的结果文字指针，其余选定状态恢复。不依赖未确认的全局 RAM 空洞，不保存跨刷新状态，不写 Flash / VM / 校准数据。

Flash PC 上限覆盖全部新增代码和末尾填充，其他 PC 范围及 `EMU_CON` 沿用原厂配置。和 B5、SUITE6 一样，扩展后的 Flash PC 区间包含旧上限与新代码之间既有的数据区。APP 扩展和额外栈均大于 SUITE6，因此本轮仍须单独进行一次整包实机验收。

## 离线验证

- 369 条新增指令按实际输出字节进行独立位域解码，并与固定版本 SLEIGH P-code 逐步对照。64 组初始状态各执行 11,698 步，共 748,672 步，结果均为 `8FF`。
- 每次执行包含 61 次短 CALL、1 次长 CALL、33 次寄存器间接 CALL；所有直接跳转都落在已解码边界，间接调用只允许落到四个已知新增函数入口。
- 全部 255 种非空组失败组合在内存中改变组返回值，逐个核对完整位图和返回状态。它们用于检查组结果组合逻辑，不冒充每组真实硬件故障。
- 另对 143 项结果断言逐项注入期望值或比较 / 操作输入故障，核对该项恰在预定断言序号触发失败，并正确清除所属位。零长度与原地移动共享期望数据时，单独改变该向量的操作字段，避免源数据与期望数据一起改变而使检查失去独立性。
- CRC 的主机位循环和独立半字节表算法交叉核对；实际固件中的位循环再由两套指令模型执行，含标准 ASCII 检查向量。解析器覆盖“错误头但 CRC 正确”和“头正确但 CRC 错误”，分别核对拒绝条件。
- 16 组原绘制参数传递检查均得到 `BW150` / `8FF`。没有仿真原绘制函数、整套 UI、中断、缓存或硬件 PSR。
- 原厂无修改重建、实验包确定性重建及反向恢复逐字节一致；第三方解析器核对完整解码容器和五个成员。7 项结构 / CRC 故障样本被离线解析器拒绝。
- 复核前六轮的 6 份冻结清单及其覆盖的 39 个文件。旧工具、旧包和旧报告保持原样，生产应用及其升级准入规则没有改动。
- 本轮实验包和原厂一致恢复包另外通过生产协议层的无设备预演，均为 `offline=true; Complete; 11088/11088`，末块 26 字节。预演日志位于 `artifacts/firmware-batch8-protocol-20261115.txt`，不将模拟应答记为新的真实抓包或设备 FF。

现有 SLEIGH 的 CALL 语义省略 RETS 自动更新，本轮继续明确补入“RETS = 调用后地址”约定。两模型的一致性不是独立硬件证明；已有 SUITE6 实测只支持之前选定路径。本轮也不等于通用 C ABI、原厂函数互操作、完整自研启动或外设控制已验证。

## 一次刷入完成的实机验收

1. 按此前已验证的官方程序刷写流程，保持控制供电和 USB 稳定、负载输入关闭，直接刷本轮 **BATCH8**。进入关于页：型号仍为 `BW150`，版本应为 **`8FF`**。
2. 在同一包上多次退出 / 重进关于页，观察结果是否始终一致、是否重启；同时核对当前使用的连接、监测、面板和可读参数。无需为八组测试分别刷包。
3. 完全断电冷启动一次，复查 `8FF` 和上述已使用功能。
4. 整轮结束后统一刷回原厂一致恢复文件，确认关于页回到 `V1.1.0`。若传输超时，记录失败进度与 APP / IAP 状态；恢复或接续核验同一轮，不重做已经通过的各个自检组。

可合并反馈为“结果码 / 重进稳定性 / 完全断电冷启动 / 原厂恢复”。不同结果码原样记录即可定位；复位则记录触发页面或阶段，再走既有原厂恢复路径。以上保留原定步骤供复现，当前整体通过的用户反馈见文首，不将计划中的重进次数自动记为已经逐项完成。
