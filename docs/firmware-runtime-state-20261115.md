## 后台行为与关于页

入口先清零自己拥有的 64 字节状态，逐字节核对参考 tick 读取器。匹配后才建立有效头标记，周期路径才允许读取 tick 和六项源。第一份快照立即采集，以后间隔至少 **100 个 OS tick** 采集一次；不假定 tick 等于毫秒或某个 Hz。源为电压、电流、功率、MOS / 探头 / CPU 温度的原始 IEEE binary32 字。

样本计数为 32 位；页面只取低 8 位，用固定 Flash 文本显示。例如 `F01 → F02` 表示快照增加，`FFF → F00` 是低 8 位正常回绕。页面读状态不增加计数、不写入后台状态；退出再进入会重新读取。页面持续停留时是否自动重绘由原厂页面决定，测试时以退出再进取值为准。

关于页先核对 **8 段共 268 字节** ROM 合约，再调用原厂任务查询导出桩，按原内核截短后的任务名 `cl24_data_t` 查找活动任务。从返回 TCB 只读核对栈字数、基址对齐和状态头，再读取计数与校验。新任务查询只发生在关于页，启动路径没有新增 OS API 调用。

| 页面结果  | 含义                                         |
| --------- | -------------------------------------------- |
| `F00…FFF` | 取得一致快照，显示真实后台快照计数低 8 位    |
| `F:ROM`   | ROM 对照不匹配，未调用任务查询               |
| `F:NONE`  | 未找到任务句柄                               |
| `F:MEM`   | 栈字段、基址或状态头不符合本包布局           |
| `F:WAIT`  | 已初始化，尚未发布第一份快照                 |
| `F:CRC`   | 选定字段异或校验不符，或已保留完整性错误标记 |
| `F:NUM`   | 曾采得非有限浮点源，错误标记保持至重启       |
| `F:BUS`   | 三次尝试均遇到更新或奇数序列，未取得一致读取 |

`F:CRC` 沿用简短诊断名称，实际为带盐异或校验，覆盖样本数、tick、错误标志、六源和独立 READY 共十个字段；它不是密码学 CRC，也不能检测任意抵消故障。序列、循环数和头标记不全部包含在异或校验中，不能宣称整个内存具备完整性保证。错误标志会参与后续校验，避免下一次采样抹掉已检测的错误。

发布使用奇 / 偶 32 位序列与 CSYNC，页面最多重试三次。电脑端只模型化选定时刻的异步发布，未模拟物理内存排序、完整调度和中断。新任务查询使用明确的活动 TCB / 易失寄存器 API 夹具，未完整执行其内部内核栈或链表操作；本轮实机需要特别区分正常启动与进入关于页后的行为。

## 一次刷入的验收顺序

1. 从已恢复的原厂状态开始，断开负载输入、保留稳定控制供电，沿用之前成功的官方 USB 流程刷入本目录 **RT1F**。
2. **先不进入关于页，观察约 60 秒。** 检查主界面、原监测更新、是否立即闪屏或出现非预期复位。这段时间后台应已经运行。
3. 进入关于页，记录完整 `Fxx`。退出到普通页，间隔约 10–20 秒再进入，记录两三次；应取得至少两个不同计数。不要要求固定每秒增量，页面读数是十六进制，低 8 位可能回绕。
4. 保留同一次刷入，继续观察约 5 分钟，期间检查常用页面 / 按键、USB 监测及具备条件的 BLE，再退出重进关于页记录计数。本轮不要求带载，也不增加私有 USB 诊断命令。
5. 完全断电冷启动一次，先检查主界面，再按步骤 3 取两次计数；本次断电后的计数从新状态重新增长，不要求正好看到 `F00`。最后刷回本目录原厂一致恢复包，检查原显示和功能恢复。

顺利时为 **1 次 RT1F + 1 次原厂恢复，共 2 次完整传输**。若闪屏，记录“刷完立即”“进入关于页”“冷启动”或具体动作，再沿已有成功流程恢复原厂，不重复刷同一失败包。`F:BUS` 若只出现一次可退出稍后重进并如实记录；其他错误码或计数不变化请保留准确码和取值间隔，不能按通过记录。旧 RT2 / RT3 继续暂停。

建议反馈：`启动观察：结果；首次与后续计数：Fxx / Fxx / Fxx，间隔约…；持续约5分钟与常用功能：结果；冷启动计数：…；原厂恢复：结果`。没有分别提供的时长、读数与测量值不会由“通过”补写为独立观测。
