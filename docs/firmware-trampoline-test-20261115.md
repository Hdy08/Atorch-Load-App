# BW150 新增区域读取与往返跳转实验（2026-11-15）

本轮承接[第三轮等长 MOV / ADD 实验](firmware-sequence-test-20261115.md)。用户于 2026-11-15 反馈“所有步骤通过，进行下一步”，第三轮约定的显示、重新进入关于页、完全断电冷启动、原厂回刷及参数 / 已使用功能核对，已按用户实测通过记录。该结果不移用为本轮新布局和新跳转的实机结果。

**2026-11-15 实测反馈：A 通过；B 在进入关于页时设备重启，判定失败。** 后续离线检查发现 B 的新增代码超出原固件配置的 Flash PC 执行上限，详见[PC 范围诊断及 B5 修正版](firmware-pc-limit-test-20261115.md)。旧 B 不再用于重复刷写。本页保留原始制作方案和离线检查记录，不将原先模型通过解释为 B 实机通过。

A 验证 APP 扩展区可读，B 原计划验证跳入扩展区短代码后跳回原流程。两包都从原厂 BW150 V1.1.0 独立制作，不叠加前轮修改。

## 用户实测结果与离线检查遗漏

用户原话为“A通过 / B失败：进入关于页设备重启”。A 按此前约定的验收项记录为用户反馈通过；没有新增抓包、Flash 回读或独立测量。B 的故障触发点是进入关于页，不能记为冷启动失败，也不能推定 B 失败后的原厂回刷已经完成，该项尚未反馈。

原固件在 `0x01E3F3FE` 加载 `0x01E9409C`，随后写入 CPU 的 `LIM_PC0_H` 寄存器 `0x001BE218`。B 的新增指令位于 `0x01E97038` 与 `0x01E9703E`，均超出该 Flash PC 范围；A 仅通过原指令读取该区域的文字。这一静态冲突与用户现象吻合，实际复位异常原因仍需 B5 对照结果或设备异常日志确认。

上一轮受限指令模型漏掉了已配置的硬件 PC 执行范围。下文的寄存器流、分支和包结构检查仍可复核，但不足以证明 B 能在硬件上执行。新增检查会将旧 B 标为范围冲突，修正版只调整上限及相关 CRC，并保留原失败样本和冻结证据。

后续 B5 约定验收已获用户整体通过反馈，支持该 PC 上限修正；旧 B 仍保留失败结论，不回改为通过。下一包采用 [SUITE6 合并自检](firmware-suite-test-20261115.md)，减少刷写次数。

## 为什么先验证扩展区

原 APP 中观察到的连续零字节并非已经确认的空闲代码空间。例如 APP 偏移 `0x45520` 的 24 个零字节周围是数据表和地址值，不能仅凭填充值或未发现字面引用就当成代码空洞。本轮没有复用原 APP 的零 / `FF` 段。

采用的方案是在 `app.bin` 末尾显式增加 32 字节，原有 APP 字节除关于页 6 字节钩子范围外均保持原地址和原内容。后面的 `cfg_tool.bin` 和 P11 资源依据目录后移 32 字节，文件内容保持原样；重新计算目录、载荷 CRC 和 SFC 编码。新增内容消耗升级包原末尾填充中的 32 字节，升级包总长保持 643,072 字节。

制作时这属于尚未实机验证的布局变化，所以设计为先用 A 读取新增区文字，再单独用 B 执行新增区代码。后续 A 获得用户通过反馈，B 失败，分别记录。

## A 包：新增区域读取

文件：`BW150-V1.1.0-AREA4-EXPERIMENTAL.bin`。

A 包把原来的版本地址加载改为加载 `0x01E97048`，通过原有绘制流程读取新增 APP 区中的 `AREA4`：

```text
01E36ACA  C8 FF 48 70 E9 01    mov r8, #0x01E97048
01E36AD0  原指令继续

新增区：
01E97038–01E97047  16 字节零填充
01E97048          "AREA4\0"
```

预期设备关于页型号行仍为 `BW150`，版本行显示 **`AREA4`**；USB 产品名仍为 `ATORCH BW150 V1.1.0`。原有 `BW150`、`V1.1.0` 及 USB 字符串均不修改。A 包不新增运行中的分支或函数调用，先检查新布局及新区域读取。

## B 包：跳入短代码并跳回

文件：`BW150-V1.1.0-JUMP4-EXPERIMENTAL.bin`。

B 包用一个 4 字节直接跳转和 2 字节填充替换原 6 字节 MOV，在新增 APP 区执行原已使用过的立即数 MOV，再直接跳回原续行地址：

```text
关于页钩子：
01E36ACA  C3 F3 B5 02          goto 0x01E97038
01E36ACE  00 00                nop                 ; 正常钩子路径不执行

新增短代码：
01E97038  C8 FF 48 70 E9 01    mov r8, #0x01E97048
01E9703E  FC F3 47 FD          goto 0x01E36AD0
01E97042–01E97047  6 字节填充
01E97048          "JUMP4\0"

原续行位置：
01E36AD0  00 E0 2D 03          jeq r0, #0, 0x01E3712E
```

预期版本行显示 **`JUMP4`**。正常新增路径执行三条指令：钩子 GOTO → 新区 MOV → 返回 GOTO，随后沿原有关于页流程运行。

这里“返回”特指直接跳回续行位置。没有增加 CALL / RTS、栈帧、寄存器压栈或硬件寄存器操作，不能把本实验成功扩大为新函数调用约定、栈语义或完整自研固件已验证。原有调用及中断仍属于完整硬件验证边界。

## 离线验证

### 布局、重编码及内容

- 新的受限调整器只允许固定布局下的 `0`、`+32`、`-32` 字节 APP 长度变化，拒绝跨越原升级包或保留区。
- 新调整器不做长度变化时，与原厂和前轮重建结果逐字节一致。
- A、B 分别重复生成得到相同二进制；对任一包缩回原 APP 并还原钩子，均能恢复原厂完整文件。
- 两个新包分别通过既有第三方解析器交叉核对，五个提取成员和完整解码容器一致。
- 原 APP 除钩子外的全部字节相同；其他四个提取成员内容相同。原顶层和保留描述不变，配置资源及 P11 的实际偏移按新目录一致后移。
- 原始文件与新包的差异只出现在三个相关目录头、原 6 字节钩子和新 / 后移的尾部资源范围。A 整包变化 3,258 字节，B 变化 3,266 字节；后移资源的重新编码也会产生原始字节差异，不能将这些数目误解为修改了同样数量的原有应用逻辑。
- 前三轮冻结清单及其覆盖的 23 个文件在检查前后分别核对，内容保持原样。用户后续实测结果记录在对应报告及摘要中，不改写冻结证据。

### 跳转和选定状态

- 对 268 个正 / 负位移、边界及固定种子随机向量，独立位域编码 / 解码与 SLEIGH 的目标一致。
- 从原始应用字节中选择 64 个可解码的同族 GOTO 编码，重新编码后字节一致。此扫描可能包含内嵌数据，不把它等同于 64 个已确认的实际控制流入口。
- 奇数目标、正向越界和负向越界均被编码器拒绝。
- 原厂、A、B 各两条显示分支与 8 种初始模式，共 **48 组、224 条选定指令步骤**；预期绘制参数分别为 `BW150` / `V1.1.0`、`BW150` / `AREA4`、`BW150` / `JUMP4`。
- A、B 另外各检查 256 组初始状态，共 **512 组、1,024 条选定钩子指令步骤**。在模型中，均到达 `0x01E36AD0`，只有 `r8` 改为新文字地址，其他通用寄存器及所提供的 SP、RETS、PSR 保持原值。
- 将 B 的返回目标故意改错后，受限路径检查按预期拒绝。此负例只在内存中执行，没有生成刷写包。

以上是选定指令及解码器语义检查，不是整机仿真。所用 q32s 模块的标志和栈语义仍不完整；模型中保持不变，不等于已经独立证明硬件 PSR、中断或全部调用行为保持不变。也没有模拟原绘制函数及中间全部调用。

## 最初验收顺序（历史计划）

控制供电及 USB 保持稳定，负载输入保持空载。A、B 各自完整验收并回刷原厂，分别记录结果。

1. **先 A。** 核对 A 文件名及摘要，刷入后确认设备关于页型号行 `BW150`、版本行 `AREA4`，USB 产品名仍为 `ATORCH BW150 V1.1.0`。
2. 退出再进入关于页，检查当前使用的连接 / 监测、可读参数及面板操作，再完全断电冷启动，确认 `AREA4` 保持。
3. 回刷原厂 BW150 V1.1.0，确认恢复 `V1.1.0`，并核对同样的参数及已使用功能。**A 任一项异常即停止 B 测试，记录现象并恢复原厂。**
4. **A 全部通过后再 B。** 使用 B 文件，关于页版本行应为 `JUMP4`；重复关于页重新进入、连接 / 监测、参数及面板核对。
5. 完全断电冷启动后确认 `JUMP4` 保持，随后回刷原厂，确认 `V1.1.0` 与上述已使用功能恢复。

上述为制作时的验收计划，本轮原样本结果为 A 用户反馈通过、B 进入关于页重启失败；不能将旧 B 记为通过。后续 [B5 单一参数对照](firmware-pc-limit-test-20261115.md)已获用户验收通过反馈，接着采用 [SUITE6 合并自检](firmware-suite-test-20261115.md)。旧 B 停止重复测试；新函数调用 / 返回约定、栈、完整外设控制及独立自研固件启动未由这份旧 B 样本建立。
