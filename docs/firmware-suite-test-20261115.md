## 一包覆盖的内容与结果显示

新程序通过原关于页钩子进入，六组结果分别占一个通过位，合成十六进制结果。正常断言失败只清除对应通过位，继续其余组；最终从 Flash 结果表选出文字交给原绘制流程。

| 通过位 | 自检项目          | 运行内容                                                               | 仅该项失败时显示 |
| ------ | ----------------- | ---------------------------------------------------------------------- | ---------------- |
| `01`   | 短直接 CALL / RTS | 参数 `17 + 25`，检查返回 `42`                                          | `S6:3E`          |
| `02`   | 长直接 CALL / RTS | 强制使用 4 字节 CALL，参数 `23 + 19`，检查返回 `42`                    | `S6:3D`          |
| `04`   | 函数指针间接调用  | 加载新增函数地址，通过寄存器 CALL，检查 `12 + 30 = 42`                 | `S6:3B`          |
| `08`   | 嵌套调用与栈恢复  | 保存 RETS、建立局部栈、暂存参数，内层调用两次，检查 `(5 + 3) + 7 = 15` | `S6:37`          |

**`S6:3F` 表示六组通过位全部置位。** 多项普通断言失败时可按位定位，例如 `S6:3C` 表示短、长直接调用两组未通过；`S6:00` 为六组均未置位。除上述正常流程中的返回值 / 读写值检查外，没有捕获 CPU 异常的通用恢复器：若指令、调用或栈本身发生不可恢复错误，设备可能先重启，来不及显示最终位图。不能凭重启猜定某一个测试位失败。

## 代码与内存安排

六组一次合计执行 8 次调用：6 次短 CALL、1 次长 CALL、1 次寄存器间接 CALL。只调用本包新增的局部辅助函数，没有新增原厂函数调用或硬件寄存器操作。

外层钩子通过 GOTO 进入包装代码，保存 RETS，并建立 64 字节局部帧保存 `r0…r7`；其中有独立的测试数据空间。嵌套子程序再使用 12 字节，包含其 RETS 和局部参数，总计最多额外使用 **80 字节栈**。选定模型验证最终 SP、RETS 和除 `r8` 外的通用寄存器恢复；`r8` 留作结果文字指针，再 GOTO 返回原 `0x01E36AD0`。

本轮不假定全局 RAM 中存在空闲区域，不新增长期 RAM 状态，不写入 Flash / VM / 校准参数，不操作负载启停或保护参数。实际任务栈余量、硬件标志位、中断和完整 UI 行为仍由实机验收约束，模型不代替这些检查。

- 按生成的实际字节执行两套受限模型：独立位域解码与 SLEIGH P-code；逐步比较分支目标、寄存器和私有栈内容。256 组初始状态各完成 144 条选定步骤，共 **36,864 条步骤**，全部回到原续行位置并显示 `S6:3F`。
- 最深额外栈用量为 80 字节；每组模型的栈边界哨兵保持不变。最终 SP、RETS、其余通用寄存器恢复。没有据此证明实际任务栈永不溢出或硬件 PSR 完整保持。

- 核对官方固定版本 ROM 的 527 条直接 GOTO / CALL，以及 118 条单独保存 RETS、POP PC、RTS 的字节 / 官方文本样例，均无不一致。
- 现有 q32s SLEIGH 对 CALL 未实现 RETS 的自动更新，本轮明确补入 `RETS = 调用后地址` 假设，两模型中均使用该约定。用户报告的 `S6:3F` 为本包所选调用与返回路径补充了实机结果，但不把同一假设下的模型一致当作独立硬件证明，也不据此证明全部调用约定；未使用语义缺失的多寄存器 PUSH / POP。
- 原关于页两条显示分支、8 种初始模式，共 16 组绘制参数检查均为 `BW150` / `S6:3F`。这只覆盖所选参数传递，未仿真原绘制函数。
- 所有新增直接分支目标落在已解码的指令边界；运行模型中的间接调用也只落到已知新增函数入口。配置的 PC 上限覆盖实际指令范围。
