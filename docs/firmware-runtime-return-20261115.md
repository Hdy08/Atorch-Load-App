## 关于页结果

预期型号仍为 `BW150`，版本位置显示 **`R1D:FF`**。末两位是八组位图：

| 位   | 检查                                                              |
| ---- | ----------------------------------------------------------------- |
| `01` | tick 读取器 ROM 字节相符，然后读取 tick 字                        |
| `02` | 电压、电流、功率、MOS / 探头 / CPU 温度六个源字为有限 binary32 值 |
| `04` | 本次调用的两个临时栈标记读回相同                                  |
| `08` | 原厂 OS 延时 ROM 桩字节相符                                       |
| `10` | 局部短 CALL / RTS：17 + 25 = 42                                   |
| `20` | 局部长 CALL / RTS：23 + 19 = 42                                   |
| `40` | 嵌套短调用，经正确的 `rets = r0` 恢复返回地址                     |
| `80` | 寄存器间接嵌套调用，经弹出 RETS 恢复返回地址                      |

例如 `R1D:BF` 缺少 `40`，`R1D:7F` 缺少 `80`；组合失败会同时清除对应位。正常值预期 `FF`，出现其他码请记录完整码。返回路径本身若异常，可能无法显示结果，不能仅靠位图保证故障可恢复。

**版本码在进入关于页时即时计算，不是后台计数或存储的后台错误记录。** 六源有限值检查不验证测量精度、单位、保护或带载能力，不能将 `FF` 当作整机稳定性证明。

1. 从已恢复的原厂状态开始，断开负载输入，保留稳定控制供电。沿用此前成功的官方 USB 升级流程，选择本目录 **RT1D** 文件。
2. **刷完先不进入关于页，观察约 60 秒。** 检查主界面是否正常、有无立即闪屏或非预期复位。此阶段验证新增局部调用和弹出 RETS 的周期路径。
3. 稳定后进入关于页，记录完整版本码，预期 **`R1D:FF`**。返回主界面后重进至少两次；若此时才异常，明确记录“首次进关于页”或具体重进动作。
4. 在本次刷入中检查常用按键、页面、USB 监测和具备条件的 BLE 功能。无需为每项重复刷入；未实际完成的项目注明未测。本轮不要求带载。
5. 完全断电后冷启动一次，先观察主界面，再复核关于页。最后使用本目录原厂一致恢复包回原厂，并检查正常显示和原功能。
