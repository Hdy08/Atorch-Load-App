## 保留原厂启动与控制系统时的三轮合并计划

若下一阶段目标为“在已验收原厂固件基础上稳定加入实际功能”，建议安排 **3 个合并验收轮次**。这是按功能范围给出的工程计划，前面需要完成相应定位、实现和离线核验；不是对未知功能或调试次数的保证。

| 轮次                        | 本包集中验证                                                                                                                                                                                                 | 通过标准                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 第 1 轮：运行环境与真实数据 | 定位稳定的主循环 / 周期调用位置，使新增逻辑按实际需要周期运行；如采用 C，验证实际编译 / 链接产物、所用调用约定和数据初始化；确认 RAM 归属、重入处理与栈余量；读取真实电压、电流、温度等并与原显示 / 监测对照 | 新增逻辑按预期周期执行，选定真实数据的数值、单位和符号一致；同时显示、按键、通信正常；受检栈 / 内存无越界和意外重启 |
| 第 2 轮：实际功能与相关接口 | 接入明确选定的功能，合并其页面、按键、通信和设置读写测试；仅覆盖该功能用到的接口与持久化字段；同包覆盖正常输入、边界、错误输入、重连及重复操作                                                               | 功能达到事先定义的行为与可观测结果；所涉设置若需保存则重启后正确；异常输入和重复操作有确定结果                      |
| 第 3 轮：整包带载与稳定性   | 在目标运行场景下同时运行新增功能、采样、显示和相关通信；覆盖持续运行、反复启停、相关模式和已有保护回归、断连重连、完全断电冷启动与最终原厂恢复                                                               | 达到预先约定的运行时长、负载 / 温度范围和功能标准；无意外启停、数据中断或复位；可恢复至已验收原厂状态               |

实际功能必须先有明确验收标准。只修改显示 / 导出等功能时可合并部分轮次；若涉及电流调节环路、保护算法或新中断 / 驱动，应按其影响重新估算，不能沿用固定三轮承诺。电气精度验证还需要相应参考仪表与测试条件，软件自检不能代替。

为减少完整传输次数，可在每包功能回归与冷启动通过后，直接刷入下一实验包，最后统一回原厂；每个候选仍从同一份原厂基线构建并保留恢复文件。**顺利时为 3 次实验包传输 + 1 次最终恢复，共 4 次完整刷写。** 中途异常恢复、修复包重测或专门验证恢复路径的传输另计，不把这项规划当作已执行事实。
