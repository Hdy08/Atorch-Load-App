# 固件页与标题栏滚动修复（2026-11-17）

## 标题栏与滚动

Windows 10 客户端标题栏启用时，根页面不再滚动或预留滚动条宽度；`main-shell` 在标题栏下方独立滚动。32 像素标题栏横跨整个窗口，窗口按钮固定在右边缘。打开和关闭 Fluent 对话框后保持相同宽度，曲线全屏仍使用原有顶层图表。

## 固件页

- 初始未选择固件时隐藏右栏，左侧检查卡片占满可用宽度。检查失败、取消文件选择和超限文件不会触发刷写。
- 右侧删除原有图标、独立型号/序列号、在线徽标及重复的选择标签，统一使用“选择 USB 设备”卡片标题。设备型号和序列号保留在下拉选项中。
- 下拉框右侧同一行放置“刷新”和“刷写”；窄屏仍保持排列，过长设备名称截断显示。
- 保留刷写确认窗口中的目标、固件及 SHA-256，删除用户指定的流程说明段落。确认前不会调用刷写命令。
- 升级期间“刷写”按钮切换为“停止”，完成、失败或取消后恢复“刷写”。继续遵循原生任务的 `cancellable` 状态，等待烧写确认时禁用停止，不另设“停止后续传输”。
- 状态区域固定四行：阶段纯文本、占满卡片内容宽度的进度条、百分比与块数、传输日志按钮。例如 `10% 1000/10000`；必要时百分比保留一位小数，整数不补 `.0`。总块数为零时显示 `0% 0/0`。
- 删除阶段徽标、重复的任务说明、日志折叠面板及路径文字。完成与失败继续使用已有悬浮通知。
- 已有升级任务切换到其它页面再返回时，继续显示其进度、停止状态和日志入口，即使文件检查组件已经重新挂载。

## 打开传输日志

`open_firmware_log` 不接收前端路径，只读取原生当前任务的日志。打开前核对文件存在，且解析后的真实路径位于应用的 `firmware_logs/` 目录内、扩展名为 `.jsonl`。

Windows 使用记事本打开日志，不依赖 `.jsonl` 的文件关联。Android 在独立文件线程将日志复制到应用缓存，通过现有 FileProvider 与 `text/plain` 的系统打开方式选择器提供只读访问；复制和打开不占用 USB I/O 执行器。macOS / Linux 预留系统文本文件打开命令，本轮未构建这两个平台。
