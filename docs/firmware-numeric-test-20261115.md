## 八组测试与结果码

`N` 标识 NUM8，后两位十六进制字符组成八组通过位图。一般结果检查失败时清除所属位，恢复包装代码状态，再继续下一组。CPU 异常或复位可能阻止最终结果显示，不能单凭重启定位某个算法。

## 明确的数值约定

- 无符号除法输出商和余数；除数为零时，商返回 `FFFFFFFF`，余数保留原被除数。使用软件位循环，没有发出硬件除法指令。
- 有符号除法向零截断，余数跟随被除数的符号。`INT_MIN / -1` 明确定义为低 32 位回绕结果 `80000000`、余数零；这是本测试函数的约定，不是声称 C 语言有符号溢出行为已获验证。零除数遵循前述哨兵约定。
- 64 位乘法、加法和减法取模 `2^64`。加减通过比较计算进位 / 借位，不依赖未建模的 PSR 进位标志。
- 64 位右移为逻辑右移；位数达到或超过 64 时返回零。0 位保留原值。
- 定点舍入用 `floor((2 × value + divisor) / (2 × divisor))` 的主机大整数表达式核对，目标代码按商与余数执行。返回的第二字仍是未舍入除法的余数。向量含 `129664 / 1000`、`6599362 / 1000` 及 32 位边界；这些是预置数据，不是设备实时读数。
- 阈值处理把原状态归一化为 0 / 1：关闭状态在 `value >= upper` 时开启，开启状态在 `value <= lower` 时关闭，第二个返回字表示状态是否改变。上下限相等时按原状态分别适用这两个条件；下限大于上限返回两个 `FFFFFFFF`。没有把该函数连接到 MOS、DAC 或真实启停入口。

## 新的 ROM 入口与证据范围

本轮沿用 B5 固定摘要的官方参考 `rom.lst`，选择其中 `__muldi3` 的 **`0x00106CC0…0x00106CF6`**，共 54 字节、21 条指令。参数按参考实现使用 `r0…r3` 传递两个数的低 / 高字，结果通过 `r0 / r1` 返回。新增包装代码以寄存器保存绝对入口地址，再作间接 CALL；没有使用尚待解释的相对地址归一化规则。

**这是参考 ROM 内部入口，不属于 ROM8 已测试的八个公开导出桩。** 当前没有固定到对应的原厂 APP 调用点，也没有物理 ROM 回读。本轮用户整体通过报告支持该入口、运行时字节核对和所选八个乘法向量在当前设备上的结果；不扩展为所有 ROM 版次、其他设备或通用 C ABI 认证。

因此在第三组调用之前，目标程序会把该地址开始的 54 字节与包内固定参考逐字节比较。全部相等才执行八个乘法向量；任一不匹配则跳过该组所有 ROM 调用、清除 `04` 位，并继续其他组，其他组通过时显示 `NFB`。该检查是一次完整字节匹配断言，不按 54 个字节重复计数。`NFB` 也可能来自乘法组内其他检查失败，不能仅凭该码排他确定字节不匹配。

离线执行逐条解释实际指令：新增代码用独立位域解码与固定 SLEIGH P-code 对照，选定 ROM 用官方反汇编表达式与相同机器码生成的 P-code 对照。没有把整个 ROM 乘法函数替换成主机乘法。参考路径内的 16 位分解、乘加、截断、插入以及保存 / 返回均参与执行。

既有 SLEIGH 缺少 CALL 的 RETS 自动赋值，以及多寄存器 PUSH / POP 的通用寄存器部分。本轮显式适配参考 ROM 的 `r6…r4` 保存帧：官方表达式模型一次分配完整帧，P-code 路径在 RETS / PC 骨架外补足对应通用寄存器动作。这种匹配约定不能独立证明完整硬件 ABI 或栈中字节顺序。新增局部函数继续使用已测试的单独 RETS、显式保存和局部栈形式。

小于 `8000` 的描述符为相对新入口的 32 位常量池位置；最高位置一的描述符内嵌低 15 位无符号整数。该表只压缩测试数据，不裁剪运算数或返回值精度。

132 字节最深路径为：外层保存 RETS 4 字节和 104 字节帧，runner 保存 RETS 4 字节，有符号除法保存 RETS 和两个寄存器 12 字节，内层无符号除法再保存两个寄存器 8 字节。ROM 乘法自身保存 16 字节，总路径小于这一上限。

模型除限定全部写入私有栈外，还要求数值 / ROM 函数的写入位于 runner 及外层状态以下，防止函数改写包装代码的局部状态。两侧保护字位于 `r6 + 0` 和 `r6 + 64`，包围 runner 的记录位置、计数、期望值、保存值和返回值槽；私有栈边界哨兵另行核对。函数不读写设备 MMIO、全局状态、VM、Flash 或校准数据。

原 APP 仍只修改关于页六字节钩子和 Flash PC 上限立即数中的两个字节，新增指令和数据位于 APP 扩展区。Flash PC 上限覆盖新指令和末尾对齐填充，其他 PC 限制与 `EMU_CON` 保持原厂值；扩展后的执行范围仍包含原上限与新增区之间既有的数据间隔。
