# USB 采样率与界面刷新

实时曲线右上角提供 `1 Hz 采样`、`2 Hz 采样`、`5 Hz 采样` 三档，首次默认 1 Hz。2026-11-16 按用户要求暂时关闭 10 Hz：界面不提供该档，原生接口也拒绝设置 10 Hz；已有 `sampling.json` 中的 10 Hz 在载入时回退为 5 Hz，之后选择有效档位会正常保存。修改后以原生服务回读的档位为准，并保存到应用配置目录的 `sampling.json`；断开、重连及重启后均恢复选择。其他无效值、配置缺失或损坏时回退 1 Hz，保存失败时显示错误并保留旧档位。BLE 由设备主动上报，隐藏 USB 档位选择，界面按约 1 Hz 刷新。

关闭原因及现有证据见 [10 Hz 相邻读数排查](usb-10hz-investigation-20261116.md)。本次未实现设备每秒十组独立更新测量值，没有修改固件、按值去重或插值。

## 调度

- `05` 实时数据查询按所选档位运行，周期分别为 1000 / 500 / 200 ms；`03` 参数查询独立保持 1 Hz，不再与实时数据轮流占用同一时间槽。
- 原生读取超时随下一个查询期限缩短，避免固定阻塞延误下次查询。错过时间槽后进入下一个槽，不集中补发历史查询。
- 前端按同一档位读取状态和采样缓存并绘图；使用固定时间基准，计算距离下一个期限的剩余时间，避免 IPC 耗时和系统定时器误差累积成频率下降。请求按顺序完成，处理超时不叠加并发刷新。
- 档位只改变上位机查询与刷新，不写入设备参数。暂停同步停止原生累计计时、缓存和兼容录制追加；继续时扣除暂停间隔，设备状态及控制回读保持可用。
- 曲线右上角提供真实 / 相对时间，首次默认真实时间并记忆选择，实时和历史共用。相对时间从首个采样点的 0 开始累计，采样行附带 `elapsedMs`，快照提供 `samplingElapsedMs`；清空后重置。最近时间范围与缩放导出使用所选坐标，CSV 中仍保留真实时间戳。所有曲线浮窗均显示到秒后两位小数。
- 内存缓存仍为 7,200 点；按 1 / 2 / 5 Hz 分别约覆盖 120 / 60 / 24 分钟。CSV 导出保留选区内原始行，不用绘图抽稀结果替代。

USB 在首次读到运行状态和实际启停变化时同步采样与记录：运行开始 / 继续，停止暂停；相同状态的后续报文保留用户手动暂停 / 继续的选择。自动建立本机 CSV，恢复后续写同一文件。自动文件附加 `ELAPSED_MS,SEGMENT_ID`，分别保留单调有效时长和暂停分段，回看曲线在真实时间空档处断开。清空会结束该自动文件并保留历史，后续采集新建文件。BLE 没有可确认的运行标志，按采样开关录制。详见 `recording.md`；本轮使用模拟传输层验证这些新行为。

调度实现见 `crates/device/src/sampling.rs`，原生接口为 `set_usb_sample_rate`，快照字段为 `usbSampleRateHz`。参数只接受 1、2、5；BLE 连接或固件升级期间拒绝设置 USB 采样率。回归覆盖有效档位调度、工作线程、10 Hz 接口拒绝、旧设置回退和界面档位。下方实机记录只涵盖此前的 2 / 5 / 10 Hz，是历史结果；不作为本次改动的硬件验收。

## BW150 历史实测

2026-11-13，Windows USB，BW150 APP V1.1.0，序列号 924415。`tools/verify_usb_rates.py` 逐档只发送 `03` / `05` 查询，每档 30 秒收到 60 / 150 / 300 份有效遥测，未跳过查询，参数前后完全一致。查询响应最大约 2.64 ms。原始报文和发送审计保存在 `artifacts/usb-rates/raw-sweep.json`。

随后使用独立的 Windows 原生调试应用，通过真实采样率下拉框逐档测量采样时间戳和图表 Canvas 重绘时间。每档 30 秒，快照和设备参数持续正常；最终结果、完整采样行与绘图时间序列为 `artifacts/usb-rates/native-sweep.json`，三档原生截图为同目录的 `native-2hz.png`、`native-5hz.png`、`native-10hz.png`。脚本结束时断开测试连接并释放 USB。

首轮发现前端相对定时误差会使 10 Hz 档绘图降到约 9.28 Hz；修正为固定时间基准后达到约 10 Hz。首轮数据保留为 `native-sweep-before-deadline.json`，不与最终结果混用。

以上确认的是 USB 返回、应用采集和界面绘图频率。各通道数值可能重复，当前稳定输入下电压、功率的变化间隔经常约为 200 ms；没有使用外部变化信号对 ADC 进行同步测量，不能据此宣称内部测量均为 10 Hz，或推断硬件最大带宽。

## 复验

```powershell
# 独立诊断工具仍可只读探测历史 2 / 5 / 10 Hz，不代表应用开放 10 Hz
# 仅在准备进行实机复验、退出其他占用 BW150 的程序后运行
python tools/verify_usb_rates.py --seconds 30

# 构建调试应用，以独立 WebView 配置启动，并设置 ATORCH_DEBUG_PORT=9232 后运行
node scripts/verify-usb-rates.mjs

# 调度、真实工作线程及界面回归
cargo test -p atorch-device -p atorch-protocol
npx playwright test tests/ui/sample-rates.spec.ts tests/ui/themes.spec.ts
```

原生复验脚本要求新启动的调试应用未连接、无录制、无固件任务，只连接已核准的序列号；不调用设备参数写入、启动、清零或固件接口。以采集频率偏差低于 3%、绘图频率偏差低于 5%作为本次短时验收条件。
