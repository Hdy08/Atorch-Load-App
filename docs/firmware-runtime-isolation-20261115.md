## 相对失败 RT1 的调整

- **取消物理堆 / 固定 RAM 改动。** 原厂 `0xFB60` 分配器结束参数恢复，未再预留 `0xFA80..0xFAFF`；没有新增常驻状态、快照计数、极值或文本 RAM 缓冲区。
- **取消早期初始化钩子。** `0x01E3F406` 及其后原初始化字节恢复，不在执行上限刚写入后立即跳入新增区。执行上限使用用户已验收 NUM8 的相同值 `0x01E97340`。
- **缩小后台路径。** 原数据任务仍在 `0x01E06B00` 的原 CALL 位置进入新增短路径，临时保存 `r0..r3` 并检查两字栈内标记，额外栈深 24 字节；内部无嵌套 CALL。随后恢复寄存器和 SP，带原来的 `r0 = 1`、`RETS = 0x01E06B04` 进入原 OS 延时。
- **把新 ROM / 数据读取延后到关于页。** 后台短路径不直接读取 ROM 字节、OS tick 或六项监测源，只访问本次调用拥有的临时栈。用户未打开关于页时，不会执行关于页的新增读取。
- **取消私有 USB `52` 命令。** 原厂 USB 接收函数逐字节一致，使用现有原厂监测即可；本包不使用旧 RT 系列的三个私有诊断脚本。

相对原厂 APP，只有三个原位置发生修改：Flash PC 上限、原数据任务的 CALL 目标、关于页版本指针钩子。新增指令 404 字节，连只读结果表及填充使用 552 字节，仍沿用已验证的 3,200 字节 APP 扩展布局；总文件长度不变。

## 关于页结果

预期型号仍为 `BW150`，版本位置显示 **`R1B:0F`**。末两位是以下四组即时检查的位图：

| 位   | 检查                                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| `01` | 参考 tick 读取器的 10 个 ROM 字节匹配，然后读取一次 tick 变量；不匹配则不读取该变量                            |
| `02` | 电压、电流、功率、MOS / 探头 / CPU 温度六个源字为有限 IEEE binary32 值；零与负值允许，不据此验证单位或测量精度 |
| `04` | 本次关于页调用拥有的临时栈中，两字标记读回相同                                                                 |
| `08` | 原厂延时入口的 4 个 ROM 字节匹配                                                                               |

例如 `R1B:0E` 缺少 `01`，`R1B:0D` 缺少 `02`，`R1B:0B` 缺少 `04`，`R1B:07` 缺少 `08`；组合失败会同时清除相应位。出现其他结果请保留准确码，不按通过记录。

**版本码来自打开关于页时的检查，不是后台执行计数，也不是后台错误记录。** 后台没有常驻统计；不能通过多次看到 `0F` 推断后台每次调用、真实时间节拍或整机稳定性全部正常。后台接入需要结合未进入关于页前的运行、原厂数据显示 / 通信、重复操作和冷启动观察。

## 一次刷入中的验收顺序

1. 设备保持已恢复正常的原厂状态，先断开负载输入，保留稳定控制供电 / USB。使用此前已成功的官方升级流程，选择本目录 **RT1B** 新文件刷入。
2. **先不要进入关于页。** 刷写完成后观察能否正常进入监测主界面，并保持约 60 秒，检查没有再次立即闪屏、显示异常、非预期复位或负载启停。此阶段只检查后台最小接入。
3. 启动正常后进入关于页，记录完整结果，预期 `R1B:0F`。退出至正常页面再进入至少两次，区分“刷写后就异常”和“首次进入关于页才异常”。
4. 在同一次刷入中检查原来的按键 / 页面、USB 监测与此前已正常使用的 BLE 功能；不具备的测试条件注明未测。无需为每一项重复刷入。
5. 完全断电冷启动一次，先观察主界面，再进入关于页复核结果。最后回刷本目录原厂一致恢复包，确认正常显示与原有功能恢复。

顺利时为 **1 次 RT1B 刷入 + 1 次原厂恢复，共 2 次完整传输**。这只描述本包验收顺序，不能承诺之后无需修订。如果任一阶段再次闪屏，记录它发生在步骤 2、3 还是其他动作后，再沿已有成功恢复流程回原厂；不重复刷同一个失败包，不接着刷旧 RT2 / RT3。

反馈内容：启动后未进关于页的观察、完整 `R1B:XX` 码、重进 / 常用功能、完全断电冷启动、最终原厂恢复。没有实际完成的时长、读数精度、保护或带载项目，不由一句“全部通过”补写成已测。

## 离线核验与边界

- 两条路径均从实际原钩子指令开始，以字段解码和 SLEIGH P-code 对照执行，各覆盖 64 组寄存器初值；后台在进入原 OS 延时前的全部受检寄存器 / SP / RETS，与原 MOV + CALL 的状态一致。模型不执行物理 OS 延时、完整调度、中断或 MMU。
- 连续 512 次后台模型调用、边界标记和限定写入检查通过，后台非栈数据读取为 0；新增代码中的写操作仅在本次调用的 24 字节栈范围内。
- 14 个 ROM 逐字节失配、六个源各三种非有限值（18 项）、两项栈标记故障、15 个组合失败位图、128 组随机有限源值均由模型核对。tick 入口不匹配时，模型确认未读取 tick 变量。故障只存在电脑内存中，没有生成故障刷写包。
- 两条原厂绘制分支、16 个结果字符串，共 32 条选定显示参数路径核对；型号和版本参数仍由原绘制流程接收。
- 原厂物理分配器初始化、早期初始化接续、数据任务注册 / 入口和整个 USB 接收函数逐字节一致；所有新指令落在沿用的 NUM8 执行上限内，旧 / 截短上限由范围检查拒绝。
- 完整包 / 成员由既有独立解析器交叉核对，非 APP 内容与前 `0x4000` 字节保持，逆向重建与原厂逐字节相同，结构 / CRC 负例按预期拒绝。生产协议层预演结果单独记录在摘要，属于模拟应答，不是设备传输成功。
- 旧九轮证据、RT 三包及失败审计共 11 份清单、71 个文件复核保持原样。旧 RT1 失败结论不会被本包离线结果覆盖。
