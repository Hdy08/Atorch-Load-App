只读审计工具为 [audit_firmware_runtime_failure.py](../tools/audit_firmware_runtime_failure.py)。离线证据位于 `artifacts/firmware-runtime-rt1-failure-20261115/`，包括 `audit.json`、工具源码快照和单独的 `manifest.json`；该目录没有新的可刷固件。

本次复核：

- 验证旧 RT 清单 SHA-256 及其 16 个文件，验证更早 9 份清单和 53 个文件，全部保持原样。
- 从原厂基线重新生成三包的 APP 并逐字节对照冻结候选，三包一致。原厂恢复文件的摘要也保持原值。这只能排查本地交付文件变化，不能证明设备内实际内容正确。

- 追踪启动状态区首次写入与 ROM 匹配调用的顺序，确认状态写入先于 ROM 检查；检查 Flash PC 上限写入后紧邻新增启动跳转，没有额外同步指令。

## 目前能确定的范围

此前 NUM8 等已通过实验主要从关于页进入新增区，未接入 RT 系列这次新增的早期初始化与原厂数据任务循环。它们的通过结果仍保留，但不能证明这次新增运行环境正确。

RT 三包相对原厂共用以下修改位置：

| 修改                                 | 原位置       | 与本次现象的关系                                                         |
| ------------------------------------ | ------------ | ------------------------------------------------------------------------ |
| 物理分配器结束参数 `0xFB60 → 0xFA80` | `0x01E3F468` | 启动时已影响原厂内存分配；实际资源余量和映射未在设备上核验               |
| Flash PC 上限扩展                    | `0x01E3F3FE` | 旧关于页实验已验证过延后进入新增区；本次新增了上限刚写入后的立即执行路径 |
| 启动初始化跳转                       | `0x01E3F406` | 写入状态 RAM、执行 ROM 匹配，发生在正常应用任务创建前                    |
| 数据任务周期调用                     | `0x01E06B00` | 不等待进入关于页即可运行；首次任务执行也属于排查范围                     |
| 关于页版本指针                       | `0x01E36ACA` | 用户未报告进入关于页后才触发，不能以该操作作为必要触发条件               |
| USB 命令分发                         | `0x01E014F2` | 三包共享；没有抓包证明本次闪屏由 USB 请求触发，也未据此排除              |

**尚未确认唯一根因。** 目前明确的是离线验证覆盖不足：

1. **ROM 检查晚于它应保护的部分操作。** 分配器参数已经改变，状态 RAM 也先开始写入，之后才检查参考 ROM 的分配器片段。失败标志只影响后续新增读取，不能证明之前的 RAM 使用安全，也没有撤销此前的分配器修改。
2. **局部执行模型不等于完整启动 / 任务环境。** 原模型从新增入口开始，以合成栈内存运行，在返回原启动路径或进入原 OS 延时之前结束；没有模拟完整启动、分配器 / MMU、真实栈保护、调度和中断。
3. **早期执行新增区缺少硬件时序依据。** `0x01E3F404` 写入 PC 上限，紧接着 `0x01E3F406` 就跳入新增区。能确认没有额外同步指令，尚不能确认此芯片是否需要同步、写入延迟是否存在或是否导致本次现象，不能将它直接写成已定位原因。

没有捕获异常现场，因此不将闪屏武断归因于 RAM 冲突、PC 保护、栈溢出、看门狗、显示驱动或刷写损坏。

## 后续实现的约束

下一版先恢复可解释的最小启动与周期接入，不直接继续旧 RT2 / RT3。将 RAM 预留、早期执行和周期接入分开核验后，再恢复真实数据、极值统计与私有 USB 诊断；继续复用现有已通过的封包与原厂恢复路径。

新增逻辑进入前应先有已建立的执行范围和经过核验的 RAM 归属。ROM 不匹配时，应保留原厂初始化 / 分配器行为，而不是写入自定状态区之后仅显示错误。任何修订都使用不同文件名、摘要和证据目录，保留旧包及其制作时的离线结果作为失败样本。

本次完成的是失败登记、关联包停测和离线审计，**没有生成或宣称已修复的替代固件，也没有再次刷写设备**。当前设备保持用户已恢复的原厂状态；后续所需修订与实机验收次数尚不能可靠给出。
