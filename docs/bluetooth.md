# BW150 BLE 功能与协议边界

本轮日期为 2026-11-13。设备为 BW150 APP V1.1.0、USB 序列号 `924415`，广播名 `BW150_BLE`，本台地址 `00:00:00:17:BB:84`。应用通过系统 BLE API 通信，无需 Root 或原厂 APK。Root / Frida 仅用于用户授权的协议分析与交叉验收。

## 当前功能

Windows 与 Android 均支持扫描、停止扫描、连接、断开、遥测、曲线、CSV 记录和历史回看。未连接时先检查 USB，再扫描 BLE；断线后恢复自动尝试。手动管理及固件更新期间暂停自动扫描，BLE 扫描完成后再次优先检查新插入的 USB。macOS / Linux 采用同一桌面 GATT 后端，本轮未构建或实机验证；iOS 尚无原生实现。

“实时监控”提供 SET、减、加、OK 四个面板键，同一行显示；窄屏使用 Fluent 小字号，保持按钮文字完整。设备设置页移除重复的遥控面板。实时页另有分别清零电量、容量、设备计时的按钮。按键作用取决于设备当前页面；加减步长由选中的数位决定，SET 不等于直接设置某个模式，OK 可能启停负载或确认当前菜单。

四个按键直接发送。三种清零各有说明和确认按钮。操作只发送一次，失败不重发。通知使用“设置键 SET 已发送。”等简短文案；GATT 写回调只表示系统传输完成，协议不提供执行确认。

Android 在连接期间启动 `connectedDevice` 前台服务，断开时结束。CSV 由 Rust 线程持续写入，不依赖 WebView 定时器。已验证退到桌面 60 秒，新增 61 个样本并写入 CSV，进程不变；短时结果不代表所有厂商的长时间省电和锁屏行为均已验证。

## 与 USB 的区别

| 项目                                                     | BLE 当前行为                                           |
| -------------------------------------------------------- | ------------------------------------------------------ |
| 电压、电流                                               | 36 字节旧版 DC 帧，按原 APK 换算；非零量程尚未逐项对照 |
| 功率                                                     | 电压 × 电流的计算值                                    |
| 容量                                                     | 10 mAh 分辨率，不补造 USB 的小数精度                   |
| 温度                                                     | 用户已确认是 MOS 温度，与 USB 共用 `mosTemperature`    |
| 电量、电阻、风扇、运行状态、模式和目标                   | 未核准或未提供，保持 null，界面“—”、CSV 空白           |
| 精确模式与参数、阶段提示和结果、校准、恢复出厂、固件升级 | 使用 USB；本版固件的 BLE 接收入口没有对应分支          |
| 面板按键、分项清零                                       | 七条原生 BLE 命令；清零还依设备当前页面选择累计组      |

没有通过 BLE 发送 USB 参数包或升级包。原 APK 的通用背光 `0x21` / 电价 `0x22` 命令不在 BW150 接收函数的处理分支中，不展示无效控件。设备原始累计电量仍为未知，读数卡片保持“—”；记录图表、统计和 CSV 回看中的缺失电量按用户要求积分补算并标为“计算”，原始容量优先。BLE 缺少可确认的运行标志，自动记录跟随采样开关，不把 OK 按键当作已确认的启停状态。

2026-11-13 根据用户确认，将旧版 DC 帧偏移 24–25 的温度并入 MOS 温度。实时温度卡片、实时 / 历史曲线、设置与 CSV 使用同一字段，不再单列“设备温度”。旧 `DEVICE_TEMP(℃)` CSV 列导入时归入 MOS；若同时有有效 MOS 列，优先保留该值。旧设备温度曲线偏好在未配置 MOS 时迁移到 MOS。本轮协议映射依据用户确认，未新增硬件温度对照实验；CPU、探头等未知通道继续为空。

## 七条原生命令

服务 `0000ffe0-0000-1000-8000-00805f9b34fb`，订阅并写入 `FFE1`，本台属性 `0x1c`。应用使用有回复写入。FFE2 也进入同一固件处理函数，但不作为应用的备用写通道。

固定格式为 `FF 55 11 02 opcode 00 00 00 00 checksum`；按原 APK 编码，`checksum = (sum(bytes[2..=8]) & 0xff) XOR 0x44`。

| 动作     | opcode | 完整包                 |
| -------- | ------ | ---------------------- |
| SET      | `31`   | `ff551102310000000000` |
| OK       | `32`   | `ff551102320000000001` |
| 加       | `33`   | `ff551102330000000002` |
| 减       | `34`   | `ff551102340000000003` |
| 清零电量 | `01`   | `ff551102010000000050` |
| 清零容量 | `02`   | `ff551102020000000051` |
| 清零计时 | `03`   | `ff551102030000000052` |

Rust 枚举只编码以上动作，传输层再次按完整包白名单校验；Android Kotlin 层重复校验，拒绝 USB 包、未知命令、任意数据和损坏包。命令与采集在同一工作线程串行执行，要求最近 2.5 秒内有有效遥测，最小间隔 300 ms。写入超时 3 秒后关闭不确定通道，防止迟到回调归属错误；连接可由自动扫描恢复，原操作不重放。

关闭扫描窗口会停止该轮手动扫描并废弃迟到结果，随后由自动扫描继续寻找设备；前台自动扫描首次遇到缺少权限时请求一次，拒绝后不反复弹窗，可在设备管理中重试或到系统设置授权。桌面连接 / 服务发现 / 订阅整体期限 12 秒，失败清理 GATT。接收缓存有界，5 秒没有有效 DC 帧则失联，界面确认断线后重新按 USB / BLE 顺序尝试。

## 验收与复现

`scripts/verify-ble.mjs` 默认仅扫描、连接和检查遥测。显式 `--controls` 要求 USB 回读为 CC、零输入、停止状态，测试四个键后经 USB 核对目标变化和恢复，OK 如进入运行状态则通过 USB STOP 恢复。脚本不执行清零、校准、恢复出厂或刷写。`--resume-controls` 可接续同一进程的回读，避免重复发送已完成的四个键。

```powershell
# 无线调试地址以当前手机为准
node scripts/verify-ble.mjs --android=192.168.1.5:40115 --background-seconds=60
# 四键测试需要已授权且可枚举的 USB 参考接口
node scripts/verify-ble.mjs --android=192.168.1.5:40115 --controls
# Windows 用手机 USB 连接作为参考，先启动可检查的原生应用
node scripts/verify-ble.mjs --controls --usb-reference-android=192.168.1.5:40115
# 三轮重连及 CSV 采集
node scripts/verify-ble.mjs --cycles=3 --seconds=10 --record-seconds=10
# 只读系统扫描诊断，仅输出匹配设备的详情及其他设备数量
cargo run -p tauri-plugin-atorch-ble --example scan -- 00:00:00:17:BB:84
```

实机报告、截图、CSV 位于忽略目录 `artifacts/*-ble-controls*`、`*-ble-stability*`，安装包与摘要见 `validation.md`。自动检查覆盖七包编码、任意写入拒绝、无执行确认、节流、清零确认与取消、扫描迟到结果；它们不代表已对实机执行清零。
