# Atorch Load

使用 **Tauri 2 + React + 微软官方 Fluent UI React v9（Fluent 2）** 重建 ATORCH 电子负载上位机。先支持 Windows 的 BW150 USB HID，Android 共用界面与采集服务，通过独立 Kotlin 插件接入 USB Host 和 BLE。

当前版本 `0.1.0`。Windows 监控、参数读写、采样记录、CSV 回看已经接通实机；尚未达到原程序全部功能等价。只以当前连接的 BW150 验证，不推断 BW600、其他硬件版本或固件均兼容。

界面直接使用未修改的 Fluent 官方明暗主题。实时监控顶部为六张约 80 像素高的紧凑读数卡片，数值、单位和右上角标识同步曲线颜色。实时曲线独占一行，“暂停 / 继续”“清空”和“导出”位于曲线卡片左下角。“应用设置”分“外观”“曲线”两个页签，曲线偏好在页面卡片中编辑。固件更新位于“设备设置”，设备连接状态和管理入口集中在左下角，未连接为红色、已连接为绿色。样式与验证约定见 [界面与明暗主题](docs/appearance.md)。

启动读取状态后，未连接时自动扫描并连接，USB 优先，其次 BLE；未找到设备时每轮结束后等待 5 秒再试，BLE 扫描结束后再次检查 USB。已连接时保持当前连接，断线后恢复扫描；手动设备管理及固件更新期间让出自动扫描。连接后默认监测，不启动负载，也不自动恢复运行状态。USB 参数写入串行处理并等待设备回读；BLE 面板操作仅确认系统传输完成，以设备屏幕为准。

USB 与 BLE 使用不同的协议。USB 支持的字段和命令不代表蓝牙也支持；当前 BLE 监测电压、电流、计算功率、容量和 MOS 温度。按用户确认，原“设备温度”已经并入 MOS，与 USB 使用同一温度通道。未核准的电量、电阻、CPU / 探头温度、风扇和启停状态用 `null` 表示，界面显示“—”，CSV 留空，不以 0 代替。

USB 在本次连接首次读到有效运行状态、以及设备启停实际变化时，自动同步采样和记录；设备相同状态的后续报文保留手动选择。运行开始 / 继续，停止暂停；运行中手动暂停、停止时手动继续均保持到下次设备状态变化。BLE 没有可确认的运行标志，默认采样并由按钮控制。实时曲线左下角的“暂停 / 继续”控制原生服务向采样缓存追加数据，暂停期间保留已有数据，继续后接续采集；设备状态读取和负载控制仍可使用。点击“清空”时，已有数据会先询问是否放弃，确认后清除本次缓存和采样计数并重置缩放；取消或 Escape 保留数据。清空不会删除已保存的 CSV，也不会清零设备累计值。原有“开始 / 停止记录”按钮已移除。

“数据记录”只保留“当前记录 / 历史记录”两个页签，历史记录中保留本机记录库及 CSV 导入。图表与当前记录在内存保留最近 **7,200 个采样点**，完整本机文件回看不受缓存限制。USB 负载运行时自动保存 CSV，停止时暂停写入，恢复后续写同一文件；曲线采样暂停也会暂停记录。清空时结束当前自动记录，已保存文件进入历史库。BLE 未提供运行标志，按采样开关控制自动记录。Android BLE 原生前台服务继续维持接收；此前 60 秒后台记录实测不作为本轮新增自动连接和记录的硬件验收。

电量、容量仅统计累计值范围，不计算平均值；原始记录缺少其中任一项时，按实际采样间隔对功率 / 电流绝对值做梯形积分，分别得到 Wh / mAh，标记“计算”。原始有效数值（包括 0）保持不变；先补算整份记录再筛选和导出，选区不会重置累计起点。自动 CSV 及带时间元数据的导出另存 `ELAPSED_MS,SEGMENT_ID`，排除暂停时间并保留曲线断点。行为及边界见 [连接与数据记录](docs/recording.md)。

实时曲线右上角可选择 USB **1 / 2 / 5 / 10 Hz**，文案为“1 Hz 采样”等，首次默认 1 Hz，所选档位保存到应用配置并在重启后恢复；设备参数独立按 1 Hz 查询。采集与界面均使用固定时间基准，避免周期误差积累。此前 Windows BW150 V1.1.0 实机验证涵盖 2 / 5 / 10 Hz，新增 1 Hz 已通过自动回归；BLE 继续按设备约 1 Hz 上报。7,200 点在四档分别约覆盖 120 / 60 / 24 / 12 分钟。调度、实测数据和复验方式见 [USB 采样率与界面刷新](docs/usb-sampling.md)。

实时与历史曲线右上角可选择“真实时间 / 相对时间”，首次默认真实时间，选择在两处共享并记忆。相对时间从首个采样点开始累计，暂停同步停止计时、采样缓存和兼容录制，继续后扣除暂停时间。清空后重新从零开始，切换页面或时间范围保留累计起点；CSV 继续使用真实时间戳。实时与历史浮窗的秒数均保留两位小数。六张读数卡片与其它卡片统一为官方默认 medium 尺寸和 12 像素内边距，内部仍保持紧凑布局。

### BW150 固件升级

Windows / Android 的“设备设置 → 固件更新”可选择已核准的 `BW150-6321-APP-1-1-0-UPP.bin`，核对 SHA-256 后扫描 USB 设备并确认开始。升级会停止普通监测，独占 USB 发送全部分块；收到设备 FF 完成应答、恢复正常应用并重新读取待机遥测后，才显示完成。升级不会启动负载。当前只开放已实测的 BW150 APP V1.1.0 / IAP V1.0.2 接口与这份文件，不推断其他型号兼容。

开始前退出官方程序、停止录制、停止负载并移除测试输入。传输阶段可停止后续分块，末块及烧写阶段需等待完成；如果留在 IAP，重新扫描并选择同一份固件可从第 0 块恢复。Android 已在描述符检查停止后的真实 IAP 状态完成恢复，故意断电恢复尚未验证。Android 升级请保持应用在前台，APP / IAP 重新枚举时允许系统 USB 访问；可选 Root Host 会话会跨越重新枚举，断开监测后还原角色。固件传输使用 USB，BLE 提供独立监测与面板遥控。实际包格式、失败记录和完整升级证据见 `docs/firmware.md`。

### 历史记录与曲线

在“数据记录 → 历史记录 → 本机记录库”刷新列表，打开已经结束的 CSV。文件保存在应用数据目录，应用重启后仍可打开；此入口读取完整文件，载入上限为 50 MB。当前自动文件在暂停期间保留写入锁，可在当前记录查看；清空或断开后可完整打开。

当前记录、库内文件和导入文件共用回看工具。实时与回看均可勾选全部 10 项测量参数，BLE 与 USB 共用 MOS 温度；除明确补算的电量、容量外，其它缺失数据保留为空。旧 CSV 的 `DEVICE_TEMP` 列导入时归入 MOS，明确的 MOS 列有值时优先保留。输入开始 / 结束时间可查看有效点数、最小值、最大值、采样均值及每页 100 条明细；电量、容量均值显示“—”，补算项标为“计算”，其余统计跳过缺失值，保留有效的 0 和负数。实时 CSV 导出使用时间范围和图表缩放条共同选定的区间；回看 CSV 使用开始 / 结束时间与图表缩放窗口的交集，保留该区间全部原始采样行及补算值，不导出图表抽稀后的数据。

勾选的曲线参数和选择顺序自动记忆，实时监控、当前记录、历史记录共用，切换页面、打开其它文件和重启后恢复。首次默认电压、电流，文件中缺少的通道不会自动取消勾选。

同单位曲线共用 Y 轴，全部选择时为 V / A / W / Ω / Wh / mAh / °C / RPM 八条轴。按当前选中参数中单位首次出现的顺序，从左到右分配，左侧向上取半数、右侧为剩余轴；轴标签默认保留一位小数，Y 轴顶部最大刻度达到 10 时显示整数，带单位并将数位上下对齐，不再显示轴顶部单位。Y 轴数值颜色跟随对应曲线，温度轴保持中性色。轴宽按实际文字测量，窄屏通过图表内部横向滚动查看全部轴。

拖动曲线卡片底部手柄可调整高度，支持鼠标和手机触摸；图表低于 520 像素使用 5 格，达到 520 像素使用 10 格，所有单位轴同步。高度范围 240–1000 像素，实时与历史共用本机保存的高度。也可聚焦手柄后使用上下键或 Home / End 调整。实时曲线默认显示全部已采集数据，可手动选择较短时间范围。

曲线偏好统一在“应用设置 → 曲线”编辑，实时与历史共用一份本机设置。每个参数可设置上下限、颜色、0.5–3.0 线宽及 0–100% 阴影不透明度，阴影默认 0%。10 个参数使用各不相同的官方 Fluent 默认色，每张卡片提供全部 10 种预设色；颜色输入框右侧的取色器按钮打开系统颜色选择器，也可直接输入十六进制颜色。同单位轴合并所选参数的范围，未手动限幅的参数仍覆盖实际数据。未指定范围时，电压等通道从 0 起，电流正负范围对称、0 位于中间；有效负温度仍完整显示。留空或“恢复默认”重新使用默认坐标和样式。旧版偏好自动迁移，相同参数的旧配置优先使用实时设置；旧设备温度偏好仅在没有 MOS 配置时归入 MOS。曲线区域不再放置设置、温度、电量 / 容量快捷按钮或可回看点数页脚。缩放后刷新数据保留所选时间位置，可用“重置缩放”返回完整范围。

“截图”位于曲线左下角导出按钮右侧，保存当前缩放范围的图表，并排除下方范围条及其占用的底部区域；数据记录页的“导出 CSV”也位于左下角。“重置缩放”位于右下角，同时恢复横轴和全部纵轴。Windows 的 CSV / PNG 保存打开系统“另存为”，可选择目录和修改文件名；Android 使用系统“创建文档”窗口选择保存位置及名称。取消保存不写文件、不显示成功或错误提示；文件写入与设备通信分别执行。

真实时间的暂停空档断开曲线和阴影，选区落在空档时统计点数为 0。范围右端贴边时跟随最新数据，左端保持所选时间；右端移开后固定历史范围。采样统计、明细和导出只使用所选范围。鼠标静止时浮窗随刷新继续显示；悬停横轴或某个单位纵轴时，滚轮仅缩放该轴。拖动曲线和范围条时继续采样，松开后刷新最新曲线，避免刷新打断拖动。无数据时不显示中央提示。

历史文件导入同时兼容 `DateTime` 起始元数据及 `Time(D.hh:mm:ss.ms),Voltage(V),Current(A),Power(W)` 结构。支持 `="00:00:00.100"` 形式、可选天数与毫秒，以 DateTime 加相对时长还原真实时间；保留负电流及文件功率值。用户提供的 `NubiaZ70Ultra_20261002_184206.csv` 已完整导入 43,467 点，真实 / 相对时间切换、电量 / 容量积分及选区导出通过，证据见 `artifacts/record-review/charge-csv-report.json`。

### 切换测试模式

通过 USB 连接后，在“实时监控 → 负载控制”当前模式卡片内部右侧点击“切换”，在弹窗中选择十种测试模式之一。侧栏不再提供“测试模式”导航。应用先读取最新模式与运行状态，仅在停止时发送一次切换命令；收到对应模式回读后自动关闭弹窗，更新卡片及目标值的 A / V / Ω / W 单位。失败在弹窗内显示并保留实际模式；关闭弹窗不发送命令。切换后保留设备中各模式自己的目标值，请核对后再启动。

IR、电源、线材和 CDxn 的普通目标字段没有核准，保持 `null`，不会把专用载荷当作浮点目标。IR / POWER / CABLE / CDC / CDCDC 使用“启动专用测试”，确认当前模式后发送原应用的启停命令。CDC / CDCDC 还会检查放电电流、截止电压、充满电压和充电截止电流；设备有待处理阶段提示时，先处理提示。CDxn 的循环次数和启动参数未核准，保留设备面板启动。BLE 可通过面板遥控键操作设备当前页面，但无法直接选定模式、读取模式或解析阶段提示；这些完整流程使用 USB。

编辑目标或确认启动时会带上当时的模式，后端执行前重新查询设备；设备面板已经切换到另一模式时，操作会拒绝并要求核对新参数。

CC / CV / CR / CP 的目标值、截止电压、过流保护、过功率保护、运行时限均可直接编辑。每项按“滑动条 → 内嵌单位的官方数字输入框 → 应用按钮”排列；运行时限为一个总分钟滑动条与时、分两个输入框。滑动条保持完整连续的官方标准轨道，不显示分段，仍按所设步进调整；窄卡片将滑动条放到输入框及应用按钮上方。编辑或拖动只修改草稿，点击“应用”才写入并等待参数回读。已移除“运行状态以设备返回为准”辅助行。

| 参数 | 范围 | 上下按钮 / 滑动条步进 | 手动输入精度 |
| --- | --- | --- | --- |
| CC 目标电流 | 0–过流保护，最大 20 A | 0.1 A | 0.001 A |
| CV 目标电压 | 截止电压–100 V | 0.1 V | 0.01 V |
| CR 目标电阻 | 0.01–9999.99 Ω | 0.1 Ω | 0.01 Ω |
| CP 目标功率 | 0–过功率保护，最大 400 W | 1 W | 0.1 W |
| 截止电压 | 0–100 V，CV 时不得高于目标电压 | 0.1 V | 0.01 V |
| 过流保护 | 0–20 A，CC 时不得低于目标电流 | 0.1 A | 0.001 A |
| 过功率保护 | 0–400 W，CP 时不得低于目标功率 | 1 W | 0.1 W |
| 运行时限 | 0 时 1 分–99 时 59 分 | 小时输入框 1 h、分钟输入框和滑动条 1 min | 整数小时 / 分钟 |

上下按钮和滑动条按从零开始的步进整数倍调整，例如手动输入 1.234 A 后增加到 1.3 A、减少到 1.2 A。细精度端点仍可手动填写；滑动条范围只覆盖允许范围内的完整步进。设备设置页共用保护、截止和时限控件及校验。后端在相关写入前重新读取设备参数，拒绝超范围、超精度及过期模式，不以单独 ACK 代替相应参数回读。时限复用设备原有的小时 / 分钟两条命令，按避免中间零时长的顺序仅写变化字段；中途失败停止后续写入并回显设备实际字段。

### 阶段控制与专用结果

实时页的“专用测试与阶段控制”显示设备电阻通道、功率、采集峰值及原始状态 / 提示码。CDC / CDCDC 提示出现时，可按设备支持的选项选择返回、继续上一轮放电、清除数据并开始新一轮放电、确认。每项动作有确认对话框；后端重新读取模式和提示，仅在与确认时一致时发送一次，并等待遥测回读，单独的 ACK 不计为阶段完成。

提示类型 2 与 3 的“新一轮放电”指令值不同，界面按实际提示生成按钮；未核准的提示只显示原始信息。提示码不是充电 / 放电阶段编号，当前不据此显示虚构的阶段、终止原因或合格判定。

观察到同一专用模式从运行变为停止时，保存运行中最后读数与停止时读数，并保留本次采集峰值。连接时已经在运行会标明记录不完整；切换模式或失联不算完成。停止记录在本次连接内最多保留 100 条，可导出 CSV，重连前请保存。字段和阶段命令证据见 `docs/special-tests.md`。

### 固件握手离线预演

在“设备设置 → 固件更新”选择原厂 `.bin`，应用识别已知 AC632N 封装，显示 SHA-256、CRC16、块数、尾块大小、AA 握手及首尾 CC 数据包。“离线预演升级握手”使用真实文件的全部字节，模拟 BB / DD / EE / FF 应答并逐块核对 CRC 和序号，不访问 USB、不进入 Bootloader，可以在监测期间运行。

已在 Windows 和 Android 原生应用中核对 BW150 的 11,088 块和 BW600 的 12,288 块。文件名型号仅作为提示，不能证明固件内容兼容。官方完整传输已核准满块保留全部 58 字节数据、仅省略 CRC 高字节，实机入口另外精确核对文件摘要及 USB 接口；协议细节与恢复边界见 `docs/firmware.md`。

## Android

工程已生成并纳入源代码，最低 Android 8.0 / API 26。USB 连接要求手机具有 USB Host / OTG；通过 OTG 数据连接 BW150，在应用中扫描并在系统弹窗允许 USB 访问。应用仅申请所选 VID/PID 设备的访问权，导出使用系统文件保存界面，不申请整盘存储访问。

### 蓝牙连接

1. 给 BW150 供电并开启设备蓝牙，断开“电能表 / E-test”等其他应用与它的连接。
2. 打开 Atorch Load 的“连接设备”，切换到“蓝牙”。首次扫描在系统弹窗允许“附近设备”权限。Android 11 及更早版本使用系统要求的定位权限和定位服务进行 BLE 扫描。
3. 扫描约 6 秒后选择 `BW150_BLE` 并点击“连接”。收到通知后自动开始监测，可查看曲线、记录 CSV 和手动断开重连。

普通蓝牙使用 Android BLE API，不需要 Root，也不需要安装“电能表”应用。Windows 和 Android 均开放 BLE，桌面端使用系统 GATT 后端。连接方式同时只保留一个，切换连接时先关闭原连接；失联不会自动重发命令或重新连接。

协议依据来自用户提供的 `电能表.apk`（E-test 1.0）及真实 BW150 通知。此设备通过 `FFE0 / FFE1` 提供旧版 36 字节直流帧，实测每秒约一条、分成 20 + 16 字节通知。容量按该协议提供的 10 mAh 分辨率显示（本次 `6620 mAh`），不会补出 USB 的小数精度；功率为电压 × 电流。温度通道已根据用户确认归入 MOS，CPU / 探头温度继续为空。

本轮已结合原 APK、BW150 固件接收函数和 USB 回读核准 SET / OK / 加 / 减，以及电量、容量、计时三条分项清零命令。连接后使用“蓝牙面板遥控”；OK 需确认，清零还需勾选已保存数据。按键作用和步长取决于设备当前页面，设备没有执行确认或运行状态回传。精确模式 / 参数、校准、恢复出厂和固件升级继续使用 USB。协议、七条命令和验证范围见 `docs/bluetooth.md`。

### USB 与可选 Root 直连

实测手机 `22061218C`（Android 15 / API 35）和 `PJZ110`（Android 16 / API 36）在默认 USB 角色下，C-C 直连没有枚举到 BW150；切换 USB Host 后均可连接。`22061218C` 的普通 OTG 连接也已通过。扫描窗口会区分“不支持 USB Host”“系统尚未识别外设”和“存在其他 USB 外设”，避免将物理连接问题混同为 USB 授权失败。当前仅连接 `0483:5750`。

对于已经 Root、支持 USB Host 的 Android 设备，可在“连接设备”窗口中尝试 **Root USB-C 直连**：

1. 保持手机与已供电的 BW150 通过 C-C 数据线连接，打开“连接设备”。
2. 开启“Root USB-C 直连”，并在 KernelSU / Root 管理器中给 **Atorch Load 应用本身**授权。ADB 的 Root 授权不能代替应用授权。
3. 扫描到 BW150 后点击“连接”，在 Android 系统弹窗中允许 USB 访问。

该选项默认关闭，启动应用和普通扫描不请求 Root。启用后临时切换 USB 控制器到 Host，正常断开设备、手动关闭开关或未连接时关闭连接窗口会还原原角色。应用被强制结束时，恢复记录保留；下次打开连接窗口点击“恢复 USB 角色”，完成恢复后再重新启用。Root 被拒绝、超时或恢复失败会在连接窗口显示错误。

Root 直连已取消机型白名单。手动开启后，原生插件通过 Root 只读探测 `/sys/class/usb_role/*/role`，仅在存在唯一可用、可写的接口且当前角色为 `none` 时切换 Host。没有接口、接口不可写、存在多个候选或 USB 已处于其他会话时，会显示具体原因并停止操作。记录中同时保存接口路径和原角色，恢复时使用同一接口；旧版恢复记录仍兼容。

开放尝试不代表所有手机都能直连。系统仍需提供可用的角色切换接口与驱动支持；当前自动检测范围是 Linux USB role-switch 接口，只有 Type-C 或厂商专用接口的系统需要另行验证。普通 OTG 连接无需开启此功能。

构建需要 JDK 17+、Android SDK / Build Tools、NDK 和相应 Rust Android target。以 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME` 指定自己的安装路径。`scripts/tauri.mjs` 会识别本机已有的常用路径，并为子进程补充 Cargo、Node 的 PATH。

```powershell
npm run android:build -- --debug --target aarch64 --ci
npm run android:dev -- --target aarch64
```

ARM64 调试 APK：`apps/app/src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`。已在上述 Android 手机通过扫描、USB 连接、持续遥测和三轮断开重连验证。USB 请求在连接期间复用，读取超时不取消和释放待完成的请求，修复了旧实现连接后在 `usb_request_wait` 中原生崩溃的问题。Android PNG / CSV 系统保存已在 `22061218C` 验证；参数写入和后台长期采集仍需分别验收，正式发布需另行配置签名。

已有 Android 工程时无需重复 `android:init`。重新生成工程会覆盖定制的 `BuildTask.kt`，该文件处理了 npm workspace 下 Node CLI 的路径；重新生成后需恢复这一调整。

## 实机验收

`scripts/verify-windows.mjs` 是明确调用的硬件测试，会原值写回目标参数并发送 STOP，不会启动负载。仅在设备待机且开发实例开启调试端口时运行：

```powershell
# 先在另一个终端运行 npm run dev
$env:ATORCH_DEBUG_PORT='9223'
cargo run -p atorch-app
# 再在另一个终端
node scripts/verify-windows.mjs
```

调试端口只在 Windows debug 构建且显式设置该环境变量时启用，release 不开启。脚本检查真实数据、参数保持、录制、导出、原 CSV 导入和重连，报告保存到忽略目录 `artifacts/`。

只想检查当前数据时使用 `node scripts/verify-windows.mjs --read-only`，不会修改设备参数。追加 `--verify-csv` 可核对新录制及导出的电阻、电量、容量字段。UI 回归测试中的实时数据为明确的 IPC 测试夹具，用于触发持续刷新，不代表硬件验收结果。

Android 调试 APK 启动、通过普通 OTG 连接后，可以使用无线 ADB 连接的设备地址运行只读通信与重连回归：

```powershell
node scripts/verify-android.mjs <ADB_SERIAL> --seconds=90 --cycles=3
# BLE：只读采样、重连及本地录制检查
node scripts/verify-android.mjs <ADB_SERIAL> --bluetooth --seconds=60 --cycles=3 --verify-recording
```

脚本要求当前没有录制任务，会连接设备、查询遥测并执行指定次数的应用内断开重连，不修改设备设置或启动负载。ADB 路径使用 `ADB` 环境变量，或从 `ANDROID_HOME/platform-tools` 查找；当前 Windows 开发环境回退到 `C:/Android/Sdk`。结果保存到 `artifacts/android-verification.json` 和 `artifacts/android-connected.png`，测试完成后保持连接。它依赖调试 APK 的 WebView 调试接口，不适用于正式 release APK。

蓝牙模式的报告和截图分别为 `artifacts/android-ble-verification.json`、`artifacts/android-ble-connected.png`，录制回读为 `artifacts/android-ble-recording.csv`。该轮旧记录使用独立的 `DEVICE_TEMP` 列，新版导入时归入 MOS。`--verify-recording` 会显式启动短暂录制并停止，检查缺失字段仍为空；不触碰设备的累计计数器。

本轮新增 `scripts/verify-ble.mjs`：默认只读，`--cycles=3 --seconds=10` 检查手动重连，`--record-seconds=10` 检查桌面录制，Android 使用 `--background-seconds=60` 检查退到桌面的持续采样。显式 `--controls` 才测试四键，需要已授权且可枚举的 USB 参考，按实际面板数位核对加减并最终执行 USB STOP；不执行清零。脚本中断可用 `--resume-controls=<报告>` 接续同一进程，避免重发已完成的四键。详见 `docs/bluetooth.md`。

当前 Windows 安装包为 `artifacts/Atorch-Load-windows-chart-interaction-setup.exe`，Android ARM64 debug APK 为 `artifacts/Atorch-Load-android-chart-interaction.apk`。两平台包含真实时间空档断线、范围末端跟随、选区统计、静止浮窗、各轴滚轮缩放、持续拖动、USB 首次状态及启停边沿自动同步采样 / 记录，以及新的导出 / 截图 / 重置按钮布局；导出和截图在手机上也保持相邻。此前自动连接、记录库、累计量补算、1 Hz 记忆、MOS 温度合并、外部 DateTime CSV、选区导出和系统保存窗口保留。源码及文件摘要见 `artifacts/chart-interaction/delivery.json`；本轮未执行安装或新增硬件验收。此前验收包保留，完整验证范围见 `docs/validation.md`。

`scripts/verify-review.mjs --port=9223 --png --csv` 在调试版 Windows 原生窗口中验证本机记录回看及文件保存。Android 使用 `--android=<ADB_SERIAL>`；`--png` / `--csv` 会创建新文件，需要完成系统保存对话框。省略这两项只打开现有记录，不修改设备；`--probe` 仅读取连接和录制状态。报告与截图保存到 `artifacts/*-data-review.*`。

`node scripts/verify-modes.mjs` 是显式的 USB 模式切换实机检查：要求负载停止、输入为 0 V、没有录制任务；通过原生界面依次进入 10 个模式，检查模式回读、停止状态和共享参数，最后恢复原模式及其目标值。不发送目标值、启动、清零或校准命令。默认连接调试端口 9223，可用 `--port=<PORT>` 或 Android `--android=<ADB_SERIAL>`；报告与截图为 `artifacts/*-mode-switch.*`。本轮已在 Windows 和 Android USB 验证。

手机已通过 BLE 连接时，`node scripts/verify-modes.mjs --android=<ADB_SERIAL> --bluetooth-read-only` 检查实时页保留面板遥控且不暴露 USB 精确模式控制，并截图，不发送控制命令；对应报告为 `artifacts/android-ble-mode-ui.*`。

`node scripts/verify-special.mjs` 在 Windows 原生调试窗口中检查本地 BW150 / BW600 参照固件并预演完整逻辑传输，核对真实 SHA-256、分块数、文件拒绝路径及监测不中断。Android 使用 `--android=<ADB_SERIAL>`，要求调试 APK 已启动；报告为 `artifacts/*-special-firmware.json`。此脚本不发送阶段选择、启动、清零、进入 Bootloader 或刷写命令。
